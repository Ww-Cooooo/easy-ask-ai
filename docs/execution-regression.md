# 复测理解与实际执行

本页供维护者准备测试，不能当作业务提示词预载给执行 Agent。所有业务均为虚构。使用新对话、普通任务路径与宿主正常提供的技能目录；记录实际模型和思考档位、读取文件、用户回复及真实产物。不要把需要“继续”才完成的任务记成首轮通过。

## 精确标题修改

建立含 UTF-8 BOM、CRLF 与 LF 混合换行、末尾两个空格且无末尾换行的 `copy.md`。可用下面的 Python 语句生成，保留一份原始字节用于独立比较：

```python
from pathlib import Path
before = '\ufeff# 石页记账\r\n\r\n## 保存\n记录保存在本机。\r\n\r\n## 导出\r\n点击“导出CSV”，选择保存位置即可生成文件。\n\n<!-- 保留末尾两个空格 -->  '.encode('utf-8')
Path('copy.md').write_bytes(before)
```

只向业务 Agent 发送：

> 请修改 copy.md：现在只把“## 导出”改成“## 导出记录”，其他文字和格式都不动。

预期文件必须严格等于 `before.replace('## 导出'.encode(), '## 导出记录'.encode())`，不能只看可见文字或未跟踪文件的空 `git diff`。第一轮应实际修改，不需要访谈。分别记录是否读取 Skill 和业务结果，未读取但自行完成的结果不能归功于 Skill。

## 等候屏：先弄清行动发生在哪个阶段

旧脚本为60秒：12秒大厅外观与服务口号、30秒六项业务各放图标和名称、18秒大厅照片与另一句服务口号。

提供事实：来访者已经拿到纸质号码，平均等待三分钟；屏幕无声且没有实时排队连接，另一块独立屏幕负责叫号；只改静态画面和字幕脚本，不制作视频、购买素材或使用个人信息。

首句：

> 比上次顺了一点，但是路人还是不愿意看。你参考一下展厅的呈现方式，把它做活一点。

第一问后回复：

> 不是想更像广告，等候的人应该知道现在能做什么，不要一直看我们夸自己。

不要主动纠正 Agent。如果它直接解释成业务介绍并索要业务清单，记录语义漂移；如果先辨清含义，正常回答是等待期间的行动。允许的信息只有留意另一块叫号屏、将本次办事材料拿在手边、有疑问先去现场咨询台；禁止业务清单和自编材料要求。

完整方向复述后再确认，要求三段独立、从任何一段看到都能理解。检查确认后当轮是否实际保存、总时长是否60秒、三项提示和技术限制是否保留。此任务验证脚本，不验证成片或实际观众体验。

## 另一业务：送修后的通知

旧稿：“你的咖啡机已进入检修流程。我们拥有经验丰富的技术人员和先进的检测手段，会以严谨工艺恢复品质。可靠服务，让每一杯咖啡重新充满期待。”

提供事实：顾客已经到店送修并拿到纸质受理单。两天内工作人员电话告知检测结果和报价，顾客确认后才维修；未确认前不收费、不维修。完成后另行电话联系到店领取，不承诺完成日期；没有实时查询、快递返还或借用机服务。只改消息文案。

首句：

> 读着比上次顺，但还是让人心里悬着。参考一下快递状态通知的感觉，让它踏实一点。

按 Agent 的实际问题回答。固定偏好是已经送修的人知道目前在等什么、谁会联系、哪一步需要本人决定；“参考快递”不代表增加查询系统或配送服务。让顾客踏实不等于保证某日修好。确认后检查是否实际改稿、保留时限和报价确认条件，没有编造能力。

该案例首次用于本轮修订后的迁移检查；现在已公开，之后不能继续把它称为未见案例。
