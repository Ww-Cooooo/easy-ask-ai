# v0.3.1 全新用户配置安装与自动触发验证

2026-10-23，从 GitHub Release 匿名下载 v0.3.1，模拟没有维护者本机技能、规则和聊天历史的新用户。结果：本次真实 Claude Code 配置下，安装者自行找到有效用户级规则载体，补齐依赖；新业务会话自动触发 Get Clear 并完成返修，Prompt Ready 的普通请求入口也被选中。

## 测试条件

- 原始发布 ZIP SHA-256：`c923f5aad31f3ee057e4325f1f9020015e0d070785033d24878be3c151dc7e4d`。没有替换包内指令或预装依赖。
- 实际宿主 Claude Code 2.1.287；配置模型别名为 `claude-sonnet-5[1M]`，响应事件模型为 `deepseek-v4.1-flash`。不是原生 Anthropic 模型测试。
- 使用独立的 HOME、USERPROFILE 与 CLAUDE_CONFIG_DIR；初始配置中没有 Easy Ask AI、grilling、more-than-yes、个人规则和插件。基线启动列表只有宿主自带技能，MCP 列表为空；工作区祖先没有 CLAUDE.md。
- 沿用现有已授权模型连接的认证与路由，不复制个人 settings、技能、聊天或规则。未另建 Windows 账户或虚拟机：可执行程序、操作系统和网络仍共享；文件访问边界由任务约束限定，不称为操作系统沙箱。
- 安装者只获得公开包位置、安装两项 Skill、用户级接入与补装固定来源依赖的授权。没有告知正确规则文件位置，没有开发聊天或评分答案。
- 测试驱动、证据和后续业务材料与安装工作区分离。最初预检发现驱动脚本在可读范围，该轮停止并废弃，不计入通过证据；另建全新目录和会话重新执行。

## 安装观察

安装者核实重定向配置后，把两项 Skill 安装到当前配置目录的 skills 下，并在该配置目录新建 CLAUDE.md，写入两个自有标记区段。它检查到两个访谈依赖缺失，使用公开包脚本从锁定提交下载、校验和审阅，再安装 grilling 与 more-than-yes；没有借用维护者已有副本。

安装后，维护者逐项比较：两包全部 **42 个发布文件字节一致**，多出的接入记录属于本地元数据。安装者最终汇报曾把一项本地记录算进包文件数；因此本报告采用原始发布清单的 42 项比较结果，而不采用其“43 文件”的自述。

安装者将发现、加载、业务行为明确标为需要新会话验证，没有把当前会话里的复制成功当成自动触发成功。

## 新会话与实际成果

另建业务工作区与会话，输入普通的社区活动报名通知返修请求，不出现技能名、规则文件名或流程要求。

| 检查 | 结果 |
| --- | --- |
| 宿主发现 | 新会话实际技能列表包含两项主 Skill 和两项依赖 |
| 规则加载 | 会话 instructions 附件包含新配置目录 CLAUDE.md 中的两段完整规则正文 |
| Get Clear 自动入口 | 模型主动调用 Skill(get-clear)，完整读取访谈、提问、依赖说明及两项依赖 |
| 澄清与确认 | 第一轮先提出原稿相关问题；收到普通语气偏好后复述方向与约束并请求确认；两轮文件字节未变 |
| 实际执行 | 明确确认后读取执行说明，保存并回读实际通知；brief 字节不变 |
| 原意保留 | 报名截止、活动时间地点、20 人名额、先后安排与候补、免报名费但交通自理、仅拍同意者且不出镜仍可参加，均保留 |
| Prompt Ready 自动入口 | 另一新会话收到普通需求准备请求后主动调用 prompt-ready、读取相关说明和 grilling，保存需求记录并开始访谈 |

业务确认由测试驱动转达正常用户回答，没有纠错、提醒读取、手工编辑产物或将开发诊断补入业务提示。维护者核对可见工具事件、实际指令附件与文件；不把模型自述或进程成功退出当成唯一证据。

## 结论与边界

这次验证说明：**按公开 README 发起安装与接入后，新用户配置可以自行完成正确接入，并在之后的普通请求中自动选择技能；不依赖作者本机已经写好的规则。** 下载 ZIP 或复制目录本身不会唤醒 Skill，也不会自动授予修改全局规则的权限。

完整业务流程覆盖 Get Clear；Prompt Ready 本次覆盖安装、规则加载、自动入口和开始访谈，未重跑完整执行提示词交付。没有扩大为所有宿主、所有型号档位或所有未来请求必然成功，也没有把维护者核查等同于真实收件人的主观验收。本轮未修改 Skill 代码或发布包，v0.3.1 的字节保持不变。
