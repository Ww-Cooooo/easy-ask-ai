# 0.2.6 验证记录

本版包含 Get Clear 0.2.6 与未改动的 Prompt Ready 0.2.2。2026-10-21 至22日，针对“技能可见却没有读取”继续排查。这里分别记录单独安装、接入宿主工作规则和显式调用；不把完成业务任务自动算成 Skill 触发，也不承诺任意未来模型、宿主与任务都100%遵循。

## 故障层次与改动

0.2.5 曾出现 Luna / max 正确修改标题、却未读取 Skill 的情况。随后仅调整描述的候选中，11种配置共22个新对话有5次漏读，全部发生在 Luna 的明确修改；其中3份产物还改变了 BOM 或换行。初始技能列表中描述完整、路径正确，已排除这些样本“没有安装或列表不可见”的解释。可见故障是选择阶段跳过入口，无法由外部记录证明模型内部原因。失败详见[描述候选记录](../docs/validation-v0.2.6-candidate.md)，原发布版见[0.2.5 记录](../docs/validation-v0.2.5.md)。

本版采用可选的[宿主读取规则](../skills/get-clear/assets/agents-snippet.md)：收到范围内的返修请求就先读入口，再选择直接执行或访谈。规则覆盖原有作品范围，包括文案、网页、音视频、产品和方案；明确小改跳过访谈，技术报错和文件重命名不进入效果访谈。使用者选择项目或用户范围，按[接入说明](../skills/get-clear/references/host-integration.md)备份和合并，复制 Skill 不会自动改动全局配置。

入口缩短为分流页，完整访谈移入 `references/interview.md`。初次迁移在规范化相对链接后与0.2.5原访谈逐字相同；后续根据实测补充事实与效果确认的区别，并前移依赖读取要求。逐问、说不清时的继续方法、语义核对、完整方向确认、明确委托例外、当前任务实际返修与真实成果验收均保留。含糊分支直接列出提问方法及两项依赖，避免只读摘要。

## 接入规则后的失败仍保留

第一版宿主规则的22个新对话均读取入口，11个标题替换的独立字节检查通过，11个含糊反馈均保留原稿并提出具体问题。但额外加入的 Luna / low 句子替换直接声称工作区外路径无法访问，未调用任何工具。其启动环境包含规则且声明允许文件访问，没有实际访问失败证据；本轮没有因此直接发布。

第二版规则补上：读取前不能直接以“无法执行”结束，按真实权限核验指定路径，遵守实际限制。新的同题对话读取了入口和执行说明，却将带 BOM 的 UTF-16 文件固定按 UTF-8 解码，误称原句不存在，仍未完成修改。执行说明因此补充先查 BOM 和编码、再判定零匹配的步骤。下一次新对话正确保留 UTF-16 LE BOM、混合换行、空白和末尾状态，独立字节比较通过；它遇到脚本调用受阻后在同轮使用保留编码的宿主工具完成，未由维护者代改。

另一个中间候选代理把禁止擅自再委派误解成不能接受父任务，未调用工具。此失败保留；后续测试统一附上真实的委派授权说明，不提供技能名称、故障原因、解题方法或评分答案。独立审查又发现缩短描述时范围变窄，最终恢复原有作品范围，并重新冻结入口与宿主规则做全档复测。中间成功不冒充最终版本的全部配置通过。

恢复范围后的 Luna / high 标题任务虽然读了入口和执行说明，但在长命令被执行策略拒绝后改用补丁，增加了末尾 CRLF，回读文字没有发现。随后收紧执行说明：符合条件时默认使用精确替换脚本；规范创建、脚本调用和临时文件清理分开；失败后先核对原因并遵守权限，使用获准的其他编辑方式须先另存原始字节、计算预期替换结果，再与实际文件完整比较。失败命令中的变量不算已保存副本，也不能凭文字看起来正确宣称格式保持不变。

这次复测的22个核心案例均读取入口，11个标题修改逐字节通过，11个迎新反馈都保留原稿并提出具体问题。不过 Luna / medium 漏读了 `grilling`，不能将它标成完整依赖流程通过。这组反馈用了访谈文档已有的表达，因此又加入此前未参与修订的英文传单任务。Luna / low 读了入口、访谈和提问说明，起初也说要先问，但读到活动简报后把已知受众、时间、免费和可不分享等事实当成了效果确认，直接改稿。此失败产物保留，未由维护者修成通过。

补充的判断是：事实和限制只能限定可行范围，不能自动回答用户本轮希望采用哪种语气、重点或体验；“请改好”也不是自主决定整体效果的委托。依赖读取前移到访谈入口，明确安装检查、摘要或只读一项不等于两项都已读取。英文传单因此转为回归案例，随后各档再开新对话验证；不能再把同题成功称为未见任务的迁移成功。

之后的11个新传单对话均实际读取访谈、提问说明及两项依赖，并保留原稿、提出问题。但继续 Luna / low 的完整流程时，确认后保存的传单漏掉了成年受众。执行说明补充保留信息检查后，另一新对话保留了受众，却把“不必购买”扩成“不需要用品”。因此又补充反向核对：成稿中的条件和承诺必须有相同范围的依据，不能把不购买、不需经验、可选分享分别改成不用携带、无需准备、不分享。

接着的新 Luna / low 对话只读入口，跳过访谈和执行说明，并在收到普通偏好回答后直接改稿，未等待修改方向确认。这些失败均保留；不能用先前某一轮做对来忽略后续漏读。当前候选把“实际读取适用分支的必读文件与依赖”写入可选宿主规则，同时在入口明确区分“回答追问”和“确认本次完整改向”。入口还要求访谈后的首次编辑定位确认依据、读取执行说明并检查成稿事实。宿主规则与入口均已改变，最终核心矩阵因此全部另开新对话。

这组22个新对话均读取入口和适用分支，11个标题逐字节通过，11个反馈都先问且未改文件。但 Luna / xhigh 在问题和总结中把“不需购买、无需经验”扩成“零准备、不用用品”，还据此错误声称原稿要求带笔记本和写故事与简报矛盾。它的入口、依赖读取通过，提问中的事实理解未通过，不能混记。因此将同范围事实核对前移到必读提问指南：对照材料原句检查概括与选项，只比较表达维度，不把新业务条件塞进示例或确认方向。随后重开访谈对话；入口、宿主规则和明确执行分支未改，标题证据保留。

随后的中间候选实际完成了6个新访谈。Luna / xhigh 没有再扩大条件，但 Luna / medium 在问题后仍声称无需笔记本；工具输出确认它读到了完整核对规则，没有截断。该轮没有算作全档通过。Luna / low 虽按顺序问、等确认、保存，成稿仍删掉了原稿的携带要求；普通方向确认并未授权取消这一条件，完整流程也未通过。

因此最终改成更具体的操作：读完通用技能和示例后，单独回读与下一问相关的业务原句，记录原稿和简报实际限定的条件，再组织问题；整篇改写前也逐条保留实际参与、使用和交付条件。简报没重述不等于撤销原稿要求，表达轻松也不等于取消条件。本次只修改提问指南及“其他返修”说明，精确修改部分保持逐字一致，再启动11种配置的新访谈与低档完整流程。

汇总原始工具输出时又发现：这11份反馈中，Luna / low 的合并输出截掉了部分提问指南，Luna / medium 的依赖和技能合并输出也被截断。即使调用参数写了文件名，或模型声称读完，都不能算完整读取通过；低档成功保存且保留笔记本的产物也不能补足这项证据。因此访谈入口补充检查截断提示、按文件或片段补读的步骤，再重跑这两种受影响配置。其余9份相关材料输出没有截断，保留原证据并说明复用范围。

22份证据均观察到 Get Clear 0.2.6 入口输出，实际模型/档位与指定配置一致，启动内容包含当前完整技能描述及宿主规则。11个明确任务读取执行说明并当轮保存，维护者独立比较完整文件字节与预期结果一致，没有额外 BOM、换行或空白变化。11份反馈证据均核对过实际工具返回的完整访谈、提问指南、依赖说明及两项依赖正文；模型随后提出了贴着原稿的具体问题，提问时原稿与简报未变。核验依据是可见工具输出和文件，不是模型自报“已使用”。

**读取及分流通过不等于事实理解全部通过。** 最后复测的 Luna / medium 在给主任务转发的建议问题中，将原稿中的“may read it aloud”概括为一串要求中的“朗读”，省略了可选限定；随后选项仍提供把作品留给自己的方向。它没有取消笔记本要求，也未提前编辑，但这条转述不准确，保留为未解决观察。前一轮把原稿已有的“免费”概括为缺失信息的记录也保留。本版改善入口与执行流程，不宣称彻底消除模型理解偏差；不能因为读了完整 Skill 就跳过成果核对。

最后复测的 Luna / low 对话另走完三轮：冻结第一轮读取记录和原稿后给普通偏好回答；它复述完整方向并等待，维护者核验原稿仍未变化；收到普通确认后读取执行说明、保存并回读传单。维护者通读实际文件，确认原稿的带笔记本要求、成年受众、时间、地点、免费、名额、报名方式及可选分享保留，没有新增无需用品或无需准备的承诺。父任务未提醒模型保留笔记本，也未代改文件。这验证所列流程与实际条件保留，不证明真实读者满意或每个背景句均逐字重述。

四项额外控制复用较早结果：Luna / low 的 UTF-16 LE BOM、混合换行、无末尾换行句子替换及 Luna / max 的英文句子替换均字节一致；Luna / low 的逻辑修复通过维护者运行的两项输入检查，Luna / max 的文件重命名保持字节一致，后两项未进入 Get Clear 访谈。它们使用较早宿主规则，相应精确方法与排除范围未变，不计入最终反馈矩阵。

另一份没有作者聊天上下文的 Sol / medium 对话沿公开 README 的正常链接做新读者审查，能区分两种流程、完整目录安装、同工作区交接及可选规则的范围和撤销。按其意见补上发布包文件名，并在发布前填写本记录。它未执行安装，不算额外运行验证。

## 测试条件与边界

各模型对话使用 Codex 子代理、`fork_turns=none`。核对宿主会话元数据中的实际模型/档位，以及第一次助手响应前的技能目录和完整宿主规则；不靠模型自报身份。标题任务没有业务聊天历史；反馈任务通过原稿和事实文件提供正常业务上下文。Skill 正文未预载在业务提示中，未给评分答案，也没有读取隐藏推理。

最终证据采用当前入口及宿主规则。访谈证据由最近全档矩阵中的9份完整输出及补充截断检查后的2份新对话组成；新增规则只规定遇到截断时补读，9份复用记录未出现该条件。11份标题记录来自较早完整矩阵，其入口、宿主规则和精确修改说明逐字未变，也未读取改变的提问指南。“其他返修”段落后来增加条件记录，适用于整篇改写，不适用于这些标题替换。更早的明确修改和迎新访谈记录不计入最终矩阵。额外控制任务的方法及排除范围未变，复用结果单独注明，不把复用记录说成最后一次修改后重新运行。

宿主提供正常全局技能、工具、规则和记忆，并共享文件系统；不是空白机器或操作系统隔离实验。反馈任务限定业务文件范围在其独立目录，公开参考仍可读取；这是提示级范围，不是权限沙箱。第一版规则的 Luna / xhigh 已完成读取并提出问题后，主 Agent 提醒其不用等待转发通用联网警告；未给业务改法，相关过程不隐去。最终候选另起新会话，不沿用这些开发对话。

结果只覆盖所列任务与条件，不外推总体触发率、现实活动效果或音视频制作质量。模型行为实测来自 Codex；同步技能文件或检查官方 DeepSeek Harness 的发现能力，不等于完成 DeepSeek、Claude Code、WorkBuddy 的模型行为测试。Codex 的用户级规则也不会自动成为其他宿主的工作规则。

精确修改脚本、依赖安装器及 Prompt Ready 本轮没有代码变更，已有单测范围见0.2.5及历史记录，不以重复脚本测试代替入口与业务检查。发布前检查完整技能包、相对链接、私人路径排除、候选行为一致及安装差异；发布包须匿名下载，与 Git 标签和本地安装逐文件核对。旧会话需要按宿主能力刷新或新开对话。
