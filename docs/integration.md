# 接入与排查

## 安装位置与独立使用

本仓库根目录是 Easy Ask AI 套件，不是 Skill 入口。将 `skills/prompt-ready`、`skills/get-clear` 中需要的完整目录安装到宿主实际发现的根目录。两者均自包含，依赖辅助脚本和锁定文件各随包提供；无需保持仓库中的相邻关系。

用户级安装可跨工作区发现，但项目级同名技能、禁用配置、旧对话快照和宿主列表限制可能影响本次实际使用。先查看当前技能列表中的路径与启用状态，再读文件；不覆盖使用者的未知修改。

## 在你自己的工作流明确接入

以下是可选规则，可经使用者同意写入项目或用户级指令。安装文件本身不会自动修改这些规则。

> 用户对当前成果表达“不好看”“不够高级”“没感觉”等模糊否定，且已有上下文不能确定其整体期望或关键改动边界时，在修改前读取并采用 Get Clear。按实际技能列表定位 `get-clear/SKILL.md`，一次问一个主要问题，沿回答继续澄清；确认后在当前任务执行。明确的修改和已确认方案直接执行。不要先做猜测方向的小样，也不要把模糊否定本身当作风格委托。

在领域技能中接入时，先由 Get Clear 负责此次访谈和确认，再回到领域技能完成制作与验收；不要同时运行两份相互冲突的问卷。用户已明确要求逐条问时，领域流程的批量问题或直接试样默认不能覆盖它。

回答追问只补齐需求；除非用户明确委托直接执行，Agent 仍需复述整体修改方向并等用户确认，不能改完再补问。每轮只保留一个待决定项，小的事实问题也不要与方案确认捆在一起。

## 四层证据不能混淆

1. **文件存在**：完整包可读。
2. **宿主发现**：实际列表包含正确名称、路径与启用状态。
3. **隐式选择**：正常任务没有点名技能，Agent 仍在合适时读取它。描述选择题、手工给全文、命令显式调用不能证明这一层。
4. **实际行为与结果**：读后问到点上、等回答、达到确认条件才制作，并检查成果。只读文件或宣布“使用了”不足以证明有效。

若发现但没有选择，检查描述、调用策略、同名冲突与上游领域技能路线；若已读仍直接改，检查当时的规则冲突、问答与动作，不只继续堆触发词。修改后用正常任务复核对应层次。

## 从旧安装迁移

`prompt-ready` 的名称与 `.prompt-ready/` 任务目录保持兼容。Get Clear 不加载 Clear Feedback；使用者决定替换后，移除旧的活动技能目录，保留需要的备份，并定向更新指向旧入口的项目规则。不要删除历史业务需求或把备份放进仍会扫描的技能根目录。

已经运行的聊天可能仍带旧技能清单或已读全文。宿主支持重载时刷新；否则新开聊天或显式读取新入口，准确区分“文件加载”与“宿主自动选择”。不能从磁盘移除一个目录就声称清空了所有旧会话上下文。
