# 0.2.3 验证记录

本版为 Easy Ask AI 0.2.3，包含 Get Clear 0.2.3 和未改动的 Prompt Ready 0.2.2。修复目标是：用户表达含糊的不满意时，Agent 先结合现有作品帮助澄清，持续承接回答，确认方向后再实际返修。

[0.2.2 准备流程验证](validation-v0.2.2.md)、[0.2.1 历史报告](validation-v0.2.1.md) 与 [0.2.0 历史报告](validation-v0.2.0.md) 保留原有结果和失败。过去的准备稿自查通过，不代表 Get Clear 的隐式选择或访谈效果也通过。

## 发现的实际问题

在获准审查的一段真实反馈对话中，早期“AI味重”后直接改稿发生在旧技能入口仍存在的阶段，不能归因于尚未使用的 Get Clear。之后 Get Clear 已经可见，工具记录也确认实际读取了入口、提问参考和两项依赖；但提问只是抽象的内容/语气分类，重复不满后又只让用户提供参考，没有利用已有稿件和调研材料帮助辨认差异。

因此本次不把“读过技能”记为有效执行，也不把原因简化成没有安装、缓存或缺少关键词。公开包只保留通用诊断和虚构示例，不收录真实聊天、项目材料或私人标识。

## 修改范围

- 入口明确包括“AI味重”“我不满意”“还是不对”及反复否定，并说明与领域润色、设计、重写的先后关系。
- 问题中要带入实际句子、可见表现或已知用途；领域技能的诊断仍是假设，不能代替用户确认。
- 用户说不清时提供有区分度的短例帮助辨认；不是要求用户自行定位问题或寻找参考，也不是先完成整篇改稿。
- 重复不满不等于回答了选项。保留未决项、换成更具体的一问；再次返修也重新检查新的分歧。
- 保留一次一问、确认后执行、已知事实和明确修改直接执行等原有边界。新增完整虚构示例，没有新增运行依赖、安装钩子或全局强制规则。

## 实际测试配置与隔离

通过 Codex 子代理运行 GPT-6 Luna / max，均使用 `fork_turns=none`，不继承维护聊天。请求参数与本地会话的 `model`、`effort` 字段一致；未取得底层服务路由证明。

执行者获得普通业务请求、对应虚构文件及宿主正常提供的技能入口，任务提示没有点名 Get Clear，也没有塞入正文、诊断或预期答案。主 Agent 仅转交正常业务回答与确认，没有提示应读哪个技能或怎样追问。两项正例实际主动读取 Get Clear 0.2.3、提问参考和正常依赖；由工具输出的版本与后续动作核对，不依赖自述。

文件访问边界由提示约束，子代理共享文件系统，不能称为操作系统隔离。业务用户由维护者模拟，因此流程通过不等于真实用户对审美结果满意。

## 观察结果

| 检查 | 实际结果 |
| --- | --- |
| 旧版定向对照，Get Clear 0.2.1 | 同模型、档位与虚构社区文案，初次“AI味重”能主动读取并停笔。连续两轮不明确回答后，旧版进入助手推测的“自然通知”方向确认；没有擅自改文件，但未把偏好问清。不能说旧版完全不触发。 |
| 新版相同开场，五轮完整流程 | 主动读取 0.2.3，先引用原稿具体表达。面对“说不清”和重复“不满意”，给出两轮短句对照，没有改稿。得到用途与语气偏好后复述完整方向，收到确认才写入并回读文案。最终保留活动时间、地点、受众、免费、人数限制、材料、换盆和浇水演示、养护交流及报名要求；原准备者还在交付前自行补回初次改写漏掉的浇水演示。 |
| 不同任务：交换活动方案 | 用户只说“不太靠谱，再优化”。主动读取，先以人数、登记时长等现有事实提问；用户指出问题其实是新人难参与后，沿参与方式追问，放下原先排队假设。复述确认后实际修改，保留原场地、总时长、人数及物品规则，加入可选择的帮助和无需上台的参与方式。 |
| 再次反馈 | 上述方案完成后，用户说“好点了，但还是不自在”。Agent 对照新方案中的具体互动方式再问，没有把部分肯定当作整体通过，也没有直接再改一版。 |
| 明确修改的相邻负例 | 新的独立子代理只接到替换公告标题的明确要求，直接完成，没有启动访谈；标题之后的字节保持一致。 |

这些是有限案例的行为证据。对照提供了一次具体差异，未进行足够重复试验，不能推导触发率、稳定增益或“100%不再失效”。两项新版正例覆盖了隐式选择、承接回答、确认、实际修改与回读；没有使用“文件存在”替代这些检查。

## 分发与边界

Get Clear 入口结构、相对引用及改动格式检查通过。依赖脚本未改，沿用已有测试，不把静态检查重复计作业务证据。最终行为文件与实测版本保持一致；包内 README 的安装/介绍文字随后同步更新，不改变实测流程。

本轮重新核对用户级安装与 Codex、官方 DeepSeek Harness 的发现；Claude Code 使用共享目录连接，WorkBuddy 使用用户级文件副本。文件同步、发现、当前聊天加载和模型行为分别说明。新行为实测使用 Codex 子代理；不将其算作 DeepSeek、Claude Code 或 WorkBuddy 模型执行结果。旧聊天可能仍持有旧入口，需要宿主刷新或明确读取新版本。

纯 Skill 无法强制所有宿主拦截修改。维护上同时保留可选的工作流接入规则、真实多轮回归方法和失败记录；不能靠宣称绝对触发来代替这些工作。
