# 0.2.1 历史验证

这是 0.2.1 发布时的记录；当前准备流程的补充验证见 [最新报告](../VALIDATION.md)。

日期：2026-10-20。使用 Skill Improve 检查独立执行条件，再以实际 DeepSeek 请求检查行为。[0.2.0 历史报告](validation-v0.2.0.md) 保留旧失败；[Prompt Ready 0.1.0](../skills/prompt-ready/VALIDATION.md) 保留更早的交接证据。本页不参与技能运行。

## 为什么高、低档都会中断

旧测试记录的停止原因是 **`max-tokens`，即单次输出上限耗尽**，不是账户余额不足或限流。之前的 8,192 / 16,384 上限由维护者的测试配置设置，不是官方 Harness 或模型默认值。思考占用输出额度，可能在可见回答开始前用完；`low` 也不是“必定低于某个 token 数”的承诺。

本轮检查已安装的官方 Harness 适配器，并记录实际请求中不含正文或凭据的参数：发往官方 Anthropic 兼容端点、模型 `deepseek-flash`、`thinking.type=enabled`，高低档分别为 `output_config.effort=high/low`，`max_tokens=65536`。档位没有被忽略，也没有偷偷改成 `off`。官方文档指出 `thinking.budget_tokens` 被忽略；不能把它当作有效预算开关。见 [思考模式](https://api-docs.deepseek.com/guides/thinking_mode/) 和 [Anthropic 接口](https://api-docs.deepseek.com/guides/anthropic_api/)。

旧包在新会话、65,536 上限下完成了两次诊断性首轮回答；这不是旧包完整流程通过，也不是严格的成本对照。模型输出有波动，首次业务输入和路径条件也有差异，不能把修订后的成功全部归因于 Skill 改动。当前成功案例中，高档软件执行单步输出达到 22,762，低档软件执行达到 17,276，低档课程准备达到 23,238；旧上限不足以容纳这些实际步骤。

**本轮纠正了测试上限，也改进了准备流程；没有证明普遍降低 token 成本。** 65,536 只是本轮测试条件，未修改用户的全局 Harness 配置，不作为所有任务的固定推荐。排查方法见 [接入说明](integration.md#deepseek-一直思考却没有回答)。

## 方法改动

- 每轮推进当前已能决定的问题，关键答案未得到前不推演全部未来分支；最终执行 Prompt 仍覆盖完整任务。
- 已委托的实现细节由 Agent 调查，只向用户询问会改变结果、成本或使用方式的选择。
- 关键名称、数值、日期、单位和路径保留来源；区分示例业务日、计划日和实际核查日。
- 复述前演练具体场景；交接前重新读取完整 Prompt、最新需求记录及启动指令，核算连续动作和失败后应保留的状态，记录实际修正。
- 宿主隐藏技能路径时先用正常技能加载工具，不假定依赖相邻安装，不递归寻找其他任务材料。
- Get Clear 的确认轮只交修改方向和保留边界，不能先贴完整改稿，再以“预览、确认后保存”绕过确认。

## 实测条件

Windows、PowerShell 7，实际安装的 `@deepseek-ai/dsh@0.2.1-rc.2`，provider 为 `deepseek-official`。配置及实际请求均已核对；未取得服务端底层路由证明。

新会话不继承开发聊天；技能入口限制为两个目标包及 `grilling`、`more-than-yes`，关闭默认项目指令和其他自动技能根目录。输入为虚构业务材料和正常访问边界。测试组织者逐轮扮演用户，回答业务选择，没有把开发诊断、参考答案或其他执行者产物交给业务模型。

这不是操作系统沙箱。部分探索及低档首轮在定位依赖时列过上级目录名称；未发现读取其他案例产物或诊断正文的证据，不能声称完全无法访问外部文件。发现该问题后补充了依赖定位规则，也不把文字规则当作系统访问控制。

## Prompt Ready：准备、确认、同工作区新会话执行

### 高、低档软件任务

虚构任务是离线 CSV 义卖收退款报表：每次读取全量原始记录，按业务发生日统计，退款归原支付方式，重复运行保留旧报表，错误数据不得产生看似有效的新结果。准备阶段只生成三份交接文件，没有制作业务程序。

| 流程 | 实际结果 |
| --- | --- |
| 高档准备 | 四轮普通业务交互后保存约 28 KB 的 Prompt；模型自行核对金额、路径及当前需求，未由维护者指出具体事实错误。 |
| 高档新会话执行 | 只读取保存的启动指令和任务文件，在同一工作区生成程序、说明和测试；执行者报告 25 项测试通过。维护者另做 17 组独立场景、18 次运行，全部通过。 |
| 低档准备的失败与修订 | 初稿的 Prompt 数字正确，但需求记录把样本交易日期写成了“核查日期”。因此未算完整通过。补充三文件及日期用途检查后，另开低档会话，以“需求已确认，继续完成交接检查”的正常输入续接；未告知错误位置或正确答案。模型自行读时钟、发现并修正日期，另修正条件性验收与输入格式表述。 |
| 低档新会话执行 | 使用上述复核后的约 21 KB Prompt，生成程序及中文说明。维护者另做相同范围的 17 组独立场景、18 次运行，全部通过。 |

两份程序的独立检查共 **34 组场景、36 次运行**：原始样本、重复运行、改变日期及金额后的部分退款到全额退款、无退款、UTF-8 BOM、GB18030，以及超额退款、未知订单、重复编号、退款早于订单、零金额、三位小数、NaN、非法日期/支付方式、缺失或重复表头。原始数据字节与修改时间未变，已有报表保留。

维护者独立重算样本：收款 72.10、退款 21.60、净额 50.50；支付方式净额为 35.50 与 15.00；跨日退款使其中一天现金净额为 -5.00。两个程序均符合各自确认的报表口径。没有人工修改业务代码或提供修法；命令启动及文件编码已检查，未冒充真实 Excel 界面或鼠标双击验收。

高档准备使用的是核心改动及依赖定位规则后的快照；最终“三文件日期用途”补充是在低档失败后加入。**低档结果包含一次额外独立复核，不是初稿一次正确；高档旧快照证据也不冒充最终包的全量重跑。**

### 最终完整包的全新跨领域流程

全部方法改动完成后，冻结最终分发包，以低档全新会话准备虚构的 90 分钟社区纸笔记账课程：12 名成年人、2 名志愿者、12 份纸笔、6 个计算器；免费、无报名、不采购、不使用手机或投影、不收集真实个人收支。要求详细教案和邻居群邀请。

准备者提出方案及三项结果选择，收到正常“确认，按建议”后生成约 35 KB 的完整 Prompt、需求记录和启动指令，自行核算示例。维护者没有提供纠错提示或修改产物。随后新开同一工作区的执行会话，只发送保存的启动指令及访问边界，生成两份成品并自行回读修订。三份交接文件在执行前后哈希相同。

维护者从最终成品的实际表格独立核算：11 段时间连续覆盖 09:00–10:30，共 90 分钟；两天共 15 笔交易的逐行余额、分项合计及最终余额 161 / 199 均正确；邀请中的时间、地点、人数、免费及隐私边界与教案一致。

这是**准备到实际文档制作的完整链路及纸面检查**，不是活动试办。志愿者自备现有纸笔、手表和现场家具仍是执行条件；收尾从 10:26 开始、10:28 给收拢提示有轻微表述重叠，不影响总时段，但不据此宣称每句话无瑕疵或教学效果已获真人验证。

## Get Clear：确认前不能先写完整新稿

本轮早期打印通知案例虽然主动加载技能并先问，但在用户回答偏好后直接贴完整改稿作为“待确认预览”。没有写文件仍不符合先确认方向的要求，此轮记为失败。

补充规则后，用新的虚构跑步邀请开展三轮高档会话：用户只说“没感觉、怪怪的”，未点名技能；模型主动加载 Get Clear 和两项依赖，一次问一个主要问题。收到“像邻居邀请、照顾新手、不要口号”等业务回答后，只复述方向、保留事实并等待确认；用户确认后才写入并回读成品。

维护者核对周三 19:00、滨河公园东门、3 公里约 40 分钟、成年人、免费、无需报名、自带水及雨天取消不补场等事实均保留。此项通过调用、交互顺序和文本事实检查，不代表真实用户审美接受，也不是自动触发率统计。

## 安装与静态检查

- 两个最终包通过 Skill Creator 结构检查；依赖辅助脚本原有 8 项测试通过。检查本地 Markdown 链接、私人路径和发布文件范围。
- 用户级安装的 31 个受版本控制文件逐字节等于最终测试快照；更新前核对旧安装无本地修改，未改依赖安装或全局模型设置。
- Codex 实际 `skills/list` 强制刷新，在两个工作区均发现四项用户级技能启用，未列出 `clear-feedback`。
- 官方 Harness 的真实文件技能提供器按默认根目录，在同两个工作区发现并加载两项 0.2.1 技能和两项依赖。这项检查未调用模型；业务执行证据来自上述真实模型会话，两者分别记录。
- 已打开聊天可能仍持有旧清单或已读正文；文件更新与新调用可加载，不等于所有旧聊天上下文被替换。社区版 TUI 的历史发现检查见 0.2.0 报告，本轮未重测它。

## 用量与限制

本轮诊断、失败、修订复测及执行共 **290 个返回用量的模型步骤**：`inputTokens` 400,651、`cacheReadTokens` 15,855,616、`outputTokens` 505,108、`cacheWriteTokens` 0、`totalTokens` 16,761,375。缓存字段包含多次历史回传，不能当作同等数量的新输入；这些是整轮维护开销，不是一次日常任务成本。未取得实际账单，不估算费用。

其中高档软件链路 114 步；低档软件链路含额外复核 64 步；最终课程链路 59 步；最终 Get Clear 16 步。其余为旧包诊断、开发探索及未通过的确认案例。两次测试驱动器启动失败发生在请求前；失败证据保留。所有本轮实际请求均使用已声明的思考档，没有 `off` 回退。

长文生成与反复自检仍可能消耗较多输出。有限案例不能证明所有领域一次成功、所有档位不再中断、普遍节约费用，或任意宿主中 100% 自动触发。没有 macOS/Linux 实测、真人教学/审美验收，也没有严格同条件的新旧包成本对照。原始会话、模型思考、凭据与私人路径不进入公开包。
