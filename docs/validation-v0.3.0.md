# 0.3.0 验证记录

本版包含 Get Clear 0.2.9、Prompt Ready 0.2.3。新增通用的宿主调查、安装与规则接入、分层核验、状态记录和撤销流程；不限定某几家软件，不假设规则都叫 AGENTS.md。实现由 GPT-6 Luna / max 完成，主任务审阅并安排独立验证。此前确认前自查、精确修改和准备稿校验保留，历史证据见 [0.2.8](../docs/validation-v0.2.8.md) 及其链接。

## 公开包能独立获得什么

[通用接入指南](../docs/host-integration.md) 提供尚未安装时也可交给 Agent 的启动指令。两项 Skill 各自包含完整说明、自己的规则片段及状态记录模板，单独复制后不依赖邻接 Skill、作者聊天或私人路径。安装 Agent 先查实际工具、帮助、有效配置与适用版本依据，确认作用范围及覆盖关系；按文件原生格式或宿主原生命令只修改自有部分。只安装不接入、没有持久规则、只读或无法操作 UI 时分别处理。

文件安装、宿主发现、规则写入、宿主加载、模型读取、普通业务触发及实际成果分开判断。状态记录只是线索，不继承写入授权，不凭版本号或旧成功记录证明当前仍生效；业务调用也不会自动授权全局改动。

## 独立测试及边界

新子对话使用 `fork_turns=none`，不继承开发聊天；调用参数和会话元数据分别记录了配置。测试者只得到冻结完整包、普通安装/业务请求、目标目录和实际工具入口，没有评分标准或拟修答案。文件范围通过提示限定，仍共享文件系统与正常全局规则、技能、宿主提供的记忆摘要；不称为操作系统沙箱或全新空白电脑。

安装测试使用三种虚构但可实际运行的宿主配置环境，并为复测另建独立实例。管理命令读取真实配置、列出实际安装文件、合并原生条目并产生新的加载快照；它们明确不提供模型会话 API。因此可以验证 Agent 是否正确调查和接入未知载体，不能证明任何第三方产品的模型会自动触发。

| 场景 | 实际观察 | 结论范围 |
| --- | --- | --- |
| 未知文件型宿主，完整套件 | 找到非空覆盖文件；没有写入不生效的常规文件；安装完整包，保留原有 BOM、CRLF、尾随空格等字节；新快照读到两段规则 | 调查、安装、合并、配置加载通过 |
| 未知原生设置宿主，只有 Prompt Ready 独立包 | 通过原生命令新增专属条目，保留其他设置及禁用条目；独立包被发现 | 原生接入与独立分发路径通过 |
| 没有持久规则能力的宿主 | 安装完整 Get Clear 并确认被发现；未猜写规则，明确报告不支持及行为待验证 | 降级处理通过 |
| 重复接入 | 比对安装与当前有效规则后保持原文件，不追加重复区段 | 重复安装检查通过 |
| 宿主升级、有效载体变化 | 不沿用旧路径，备份后接入新活动载体，旧文件和新文件原有内容保留 | 配置迁移通过；第一候选记录问题见下文 |
| 撤销原生接入 | 只移除本包条目，保留 Skill 以及安装后新增的其他规则和设置 | 配置撤销通过 |
| 最终候选的状态记录生命周期 | 新对话创建记录；随后另一个新对话处理宿主变化、已有无标记文件及替代文件名，并在撤销后刷新记录 | 记录创建、发现、更新、失效及撤销通过 |
| 真实 Codex 完整返修 | 最终候选在 Luna / low 中，普通含糊反馈后提问、等待偏好、核对并确认方向，确认后实际保存 | 该配置与案例的隐式读取和完整行为通过 |

上述配置环境的 Agent 为 Luna / max；真实业务回归为 Luna / low，使用本机既有、获准的 Codex 读取规则。本轮没有重跑全部型号/档位旧矩阵，也没有实际调用 DeepSeek、Claude Code 或 WorkBuddy 的模型执行这些任务。安装环境未补装访谈依赖，不将发现两项 Skill 等同于访谈依赖可用。真实 Codex 回归实际读取了已安装的 grilling 和 more-than-yes。

## 第一候选的问题与复测

第一候选完成了配置接入，但一个安装对话把默认状态记录写成无归属标记的普通文件。后续升级时，另一新对话正确迁移了规则，却只能保留旧文件并另存记录；入口又只查默认名称，不能稳定找到后续记录。这一项判为未通过，原始产物和失败保留，没有把配置合并成功当作记录生命周期成功。

最终候选增加随包模板、首次创建的成对标记和保存后回读要求；入口仅在实际 Skill 目录查找受限模式，按自有标记、Skill 身份、实时宿主与作用范围核对。无标记文件保留，替代文件也能被找到；有效载体变化和撤销会使相关旧证据失效。修改后重新冻结，在新的独立目录与对话复测受影响流程。已验证且未改变的原生配置管理、无持久支持等逻辑沿用第一候选的证据，不伪称全部场景又跑了一遍。

## 真实业务成果与发布检查

最终版维修领取通知在三个回合内完成。主任务只转达普通偏好和确认，没有指出错误或代改文件。实际工具输出包含完整入口、访谈、提问指南、依赖说明和两项依赖，确认后完整读取执行说明。确认前原稿未变；确认文字与成稿均保留必须带领取码、问卷自愿且在领取后、周二至周五 09:00–17:00、指定柜台、从消息日期起保留14天、已有服务计划覆盖维修且无需额外维修款，以及停车按常规收费。实际文件已保存并回读，简报字节未变。维护者核对可见事实和流程，不替用户验收主观语气，也不声称观察到了隐藏思考。

本轮没有改业务执行脚本，不重复未受影响的脚本矩阵。检查了两包结构、包内链接、单包引用边界、私人路径排除、原 README 背景和冻结内容。发布前同步本地安装并比对；发布后匿名下载 ZIP 与 Git 标签逐文件核对。Codex 刷新发现与官方 DeepSeek Harness 文件系统发现检查、Claude Code 共享安装和 WorkBuddy 文件同步各自只证明对应层次。没有追加其他宿主的真实全局规则，也没有将旧会话视为自动刷新。

有限案例不能保证所有宿主、模型和未来任务必然触发。通用接入的承诺是按当前实例查证、在授权范围内接入并报告真实状态，而不是给未知软件作未经验证的兼容保证。
