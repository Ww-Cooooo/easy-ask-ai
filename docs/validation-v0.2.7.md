# 0.2.7 验证记录

本版包含 Get Clear 0.2.7 与未改动的 Prompt Ready 0.2.2。针对0.2.6留下的转述偏差继续修订，并修复复测中发现的材料截断和分支误判。宿主接入规则、精确修改文件及脚本未改。本轮修改入口的分支判据、访谈读取方式、提问时的条件核对和版本号。

## 失败与修复依据

0.2.6的 Luna / medium 虽读了完整 Skill，却将“may read it aloud”并入一串要求，丢掉可选限定。[原始记录](validation-v0.2.6.md)保留这一问题，以及此前漏读、提前编辑、编码和换行失败。本版要求分别保留各个动作的约束强度，不将必须、建议、可选、禁止合并到同一“要求”或“无需”下面。提问通常只需短引一处原句；必要的概括逐分句核对，转交父任务的问题也遵守相同标准。说明使用预约与提醒的通用例子，没有写入待测活动答案。

改后新开的 Luna / medium 原案例正确保留可选分享，完整读取且未编辑；同轮另一份 Luna / low 服务通知却出现合并输出截断，未补读完整访谈。后者判为失败。因此改为默认逐文件读取必读材料，单文件过长分段，已经截断则补读，不能凭首尾出现断言完整。

随后11种配置的新服务通知对话中，9种完整读取并提问；Luna / high 与 xhigh 虽读入口，却把“被训斥的感觉、想更亲切”当成明确操作，直接整篇改写。这两份文件和失败记录保留。因此在入口补充：效果方向不等于具体操作；仅给期望感受和修改请求，不能因为事实齐全、文字短或已经想到改法就直接执行。具体替换/操作、已确认完整方向、明确自主委托分别处理。之后冻结完整候选，重新运行下表全部配置。

## 最终候选：新对话复测

任务为虚构的维修完成领取通知，普通请求是“This still feels like being told off. Please make it feel more welcoming.”，提供现稿和简报。输入没有 Skill 名称、故障诊断、评分规则或修法提示。该任务在前轮已用于发现分流错误，所以最终重测属于回归验证，不冒充未见任务迁移。

上表选用11个新初始对话，每个配置一个案例。另有一份 Luna / xhigh 虽正确读取和提问，却主动检索旧维护记忆；保留记录但不计入无开发材料的矩阵。补测在独立目录明确禁止读取记忆文件和项目历史，其余业务请求及技能未变；后续未开始的测试同样使用这一材料范围限制。最终入表记录未发现读取维护记忆文件。核对宿主会话元数据中的实际配置、首次响应前的完整技能描述和当前宿主规则，以及工具返回的入口、访谈、提问指南、依赖说明、grilling、more-than-yes正文。主任务逐一阅读问题与转达内容，对照原稿检查事实；不以文件名出现、读取命令或模型自报代替实际输出。

另开 Luna / low、high 两个明确标题替换对话。两者读取入口和执行说明，直接保存指定修改，未启动访谈。主任务独立比较完整文件字节，BOM、CRLF、末尾空格及无末尾换行状态全部保持，只有指定标题不同。这两项检查新增判据没有把明确小改送进访谈。

最终 Luna / medium 另走完三轮：提问；收到普通偏好后复述完整方向并等确认；收到“Yes, please make that change.”后读取执行说明、当轮保存。主任务在确认前核验原稿未变，确认后完整阅读实际文件，核对领取码要求、时间地点、14天从消息日期起算、现有服务计划覆盖且无需额外维修款、停车正常收费、问卷在领取后自愿填写。成稿保留这些条件，采用平静友好的开头和便于查找的实用信息。父任务没有指出遗漏、提示答案或代改产物。

**最终 Luna / low 的完整闭环未通过。** 首次提问正确且未编辑，但收到普通偏好后，确认复述前面写“需要带领取码”，后面又写成“领取时可带”，同一条回复中的条件强度不一致。主任务未把这段有误复述确认成有效方向，也未提示答案或代改文件；流程停在确认前。前一候选的 low 和 medium 成功保存且保留条件的两份产物仍保留，但不能用那次成功覆盖这次偏差。现有逐项核对说明未能稳定防止该错误，本版不宣称低档理解完全可靠或彻底免除复核。

本轮合计27个新初始对话：最初2个、读取方式调整后11个、最终14个（12个反馈，其中1个因读取维护记忆不入表；另有2个标题）。保留一次截断失败、两次分流失败和最终低档后续确认的语义失败；不写成27次全部通过。原传单回归发生在读取方式及分支判据调整之前，其输出完整；仅作为修复可选项转述的单独证据。

## 复用范围与限制

11种配置的早期标题替换、其他编码/换行控制和技术修复/重命名排除案例见[0.2.6记录](validation-v0.2.6.md)。它们是历史证据；本版只有上面的两个标题控制使用最终入口重新执行。精确修改文件和脚本未改。Prompt Ready未改，本轮没有重测其完整业务流程。

各模型对话使用 Codex 子代理、`fork_turns=none`，没有维护聊天历史，但正常全局技能、规则、工具及记忆仍可用，共享文件系统。每份业务材料放在独立目录，访问范围是提示级约束，不是操作系统沙箱。父任务代为转达普通业务回答，只核对可见工具输出和文件，没有读取隐藏推理。宿主记录证明其配置，不提供不可见服务端路由的额外保证。

有限案例不能推出任意任务和模型100%触发或理解无误，也不证明真实读者已接受语气效果。安装、发现、读取和实际行为分别验收。Codex用户级规则不会自动成为其他宿主的规则；DeepSeek Harness发现检查以及Claude Code、WorkBuddy文件同步，不算这些宿主本轮模型行为实测。

发布前检查完整包格式、引用、私人路径排除、冻结候选一致及原有背景文案保留。精确替换及依赖安装脚本未修改，沿用已有脚本测试。发布包匿名下载后与Git标签逐文件比较，本地安装也独立比对；结果见发布说明。旧对话需按宿主能力刷新或新开对话。
