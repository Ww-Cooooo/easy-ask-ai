# Prompt Ready

**把想法问清楚，把执行方案写具体，再交给模型动手。**

Prompt Ready 会通过多轮追问梳理需求，检查遗漏，并结合现有项目和材料，生成一份详细的执行 Prompt。准备完成后，它会引导你在**同一工作区的新对话**中执行，让接手的模型拥有完整背景和明确步骤。

## 为什么做这个 Skill

我平时经常使用轻量模型。一个实际感受是：只用一句话描述想法，让模型直接开工，很难稳定得到符合预期的结果。

这种“许愿式编程”把太多事情留给了模型临场判断：用户究竟想解决什么问题、有哪些没说出来的限制、应该采用什么方案、做到什么程度才算完成。换成写课程、做内容或整理业务流程，同样会遇到这些问题。

因此，我更希望先让模型担任技术监督：把需求问透，调查已有条件，补齐方案，再写出足够详细的执行 Prompt，交给新对话里的模型实施。可以用较强模型负责准备，也可以让同一个模型分两次对话完成准备和执行。

但每次都要重新交代这套流程很麻烦。面对不同类型的任务，用户也未必知道该补充哪些信息，更不一定能自己写出完整的执行说明。

**Prompt Ready 把这套准备工作做成了一个可重复使用的 Skill。你先说出想法，它负责帮助你把任务讲清楚、把方案写具体。**

## 它怎样把想法变成执行说明

1. **用 `grilling` 深入追问。**
   根据任务和你的回答逐层展开，弄清用途、使用情境、交付物、约束和验收标准。不会问完固定几个问题就草草结束，也不会让你替模型决定所有技术细节。

2. **用 `more-than-yes` 检查与补充。**
   核对方案的前提和依据，找出你可能没想到的缺项。补充涉及结果、成本或使用方式时，会带着具体建议回来确认。

3. **生成详细、可独立使用的执行 Prompt。**
   写清任务背景、已确认决定、实施方案、阶段步骤、输入输出、关键判断、检查方法和失败处理，让执行模型尽量少猜。具体写法随任务变化，不把所有工作都套进同一张模板。

4. **交给同一工作区的新对话。**
   保存完整 Prompt，并给你一条简短的启动指令。新对话先核对工作区和材料，再按说明完成任务，不需要重新翻找准备阶段的聊天。

详细程度取决于任务需要。每一段都应帮助执行者知道该做什么、为什么这样做、怎样判断做对了。它不能消除模型能力的差距，但能把原本藏在用户想法和讨论过程中的关键信息，明确交到执行者手里。

## 安装与第一次使用

需要一个能读取 Skill、访问任务文件的 Agent 宿主。依赖自动补装脚本需要 **Python 3.10+ 和 GitHub 网络访问**；没有 Python 时可由 Agent 使用宿主已有安装能力，具体见 [依赖说明](references/dependencies.md)。纯网页聊天且不能访问工作区的环境，无法直接完成文件交接。

Prompt Ready 现在属于 Easy Ask AI 套件。取得套件文件后，将 `skills/prompt-ready` 整个文件夹复制到宿主实际使用的技能目录，保留入口、参考、模板、脚本及许可证。不要把套件根目录当成单个 Skill 安装；目标已有文件时先核对修改，不直接覆盖。

在本机验证的 Codex 与 DeepSeek harness 中，用户目录下 `.agents/skills/` 可被发现；其他环境以宿主实际技能列表为准。安装后刷新或新开对话，确认 `prompt-ready` 出现在技能列表中。文件可读不等于实际自动选择。

在要执行任务的工作区调用：

```text
使用 $prompt-ready。我想做一门面向新人的课程，先帮我问清楚需求，再准备交给新对话执行的完整提示词。
```

首次运行会检查 `grilling` 和 `more-than-yes`；缺少时，在已有授权及宿主权限内从固定 GitHub 版本补装，保留已有安装及修改。安装过程不会执行下载的代码。需要宿主授权或刷新时会说明具体操作，不假装已经可用。

## 你会得到什么

默认在工作区 `.prompt-ready/<任务名>/` 保存：

- `requirements.md`：已确认需求、委托决定、调查事实和未决项，方便暂停后继续。
- `execution-prompt.md`：可独立使用的详细任务说明，包含背景、约束、材料、实施方案、所有执行阶段、验收与失败处理。
- `start.txt`：给同一工作区新对话的一条启动指令。

已有项目约定时沿用其规划目录。只有需求得到确认、重要未决项解决后，才生成最终可执行版；你明确要求先出草案时，会标明尚未确认的部分。

可查看一份[完整执行 Prompt 示例](examples/library-book-swap.md)：它来自虚构的旧书交换活动试用，展示详细程度、执行步骤与验收方法，示例路径需要替换后才能用于实际任务。

生成后，**请在同一工作区创建新对话**；宿主支持选择模型时，选择你希望用于执行的模型。打开 `start.txt` 并复制其中的完整指令到新对话，它不会自动切换模型。新对话先核对路径和材料，再执行。默认不代你开对话、不自动开始制作，也不自动发布任何成果。

## 环境与数据边界

准备过程读取本任务相关的项目规则与材料，输出留在工作区。研究与事实核验可能按任务需要使用联网工具，范围受用户授权和宿主规则约束。依赖脚本只向锁定的 GitHub 下载端点请求公开包，不读取凭据、不上传任务文件、不修改现有 Skill；下载后还需 Agent 审阅内容。Agent 对话及领域工具仍遵守各宿主自身的数据处理规则。

模型是否正确追问、方案是否有效，需要实际任务检验；详细 Prompt 不能保证小模型在所有任务上达到相同水平。源文件安装、宿主发现、真实业务效果是不同的验证范围。本包保留 [0.1.0 历史验证](VALIDATION.md)，新版跨宿主测试见 [套件验证记录](https://github.com/Ww-Cooooo/easy-ask-ai/blob/main/VALIDATION.md)。
