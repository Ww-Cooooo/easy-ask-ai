## 制作时的 Skill Improve 检查

按已确认的需求核对完整包，重点补齐：

| 原有意图或潜在缺口 | 包内处理 | 核查方式 |
| --- | --- | --- |
| 深入问清需求，但“完全理解”无法直接判断 | 具体情境、结果、约束、反例、委托及用户复述确认共同决定收敛 | 检查访谈方法与代表任务中的问题和需求复述 |
| 覆盖广泛任务，容易退化成软件开发问卷 | 从使用情境推导问题，给多领域的调查、操作和验收区别 | 用非软件业务任务检查交接产物 |
| 补充建议可能悄悄改写用户需求 | 结果性变化回到追问，已委托实现可自主推进 | 对照需求记录与最终 Prompt |
| 极详细 Prompt 可能只有篇幅、没有执行方法 | 阶段输入输出、动作、条件、依据、检验和恢复；保留完整任务 | 审阅真实生成的执行 Prompt |
| 新窗口不能继承聊天，也不一定在相同目录 | 主 Prompt 自包含，启动指令核实工作区及材料 | 新鲜上下文交接检查 |
| 业务测试中需求记录只追加，保留了多个相互冲突的“当前阶段” | 要求唯一置顶当前状态，已解决问题移出未决，旧方案标为历史并指出替代决定 | 新鲜上下文续接复测；原始记录单独保留 |
| 自动补装不能依赖作者电脑 | 固定来源与提交、Python 标准库脚本、明确宿主路径、无覆盖及失败恢复 | 下载/安装实测与异常路径测试 |

- 依赖辅助脚本 8 项单元测试通过，覆盖摘要变化、选包与许可证、路径越界及大小写冲突、链接、已有定制保留、中文空格路径、残缺发现和中断保留。首轮一项测试因 Windows 的 ZIP 夹具自动规范化反斜杠而失败，改为直接检验原始路径校验器后通过；未以放宽路径校验来消除失败。

- 业务准备独立运行：请求配置 `gpt-6.1-sol / medium`，`fork_turns=none`。以虚构的社区旧书交换活动为正常输入，多轮追问、用户业务回答、补充发现所有权冲突、再次选择与需求复述确认后，生成完整执行 Prompt 与启动指令。主 Prompt 包含具体纸笔操作、90 分钟分配、预算口径及逐项验收。[完整示例](examples/library-book-swap.md) 已替换测试机路径。

- 交接后的独立执行：另一个 `gpt-6.1-sol / medium`、`fork_turns=none` 执行者只获得最终 Prompt 和必要工作区信息，没有读取准备聊天、需求记录或本 Skill，实际生成完整 `activity-kit.md`。创建者复核完整材料，计算确认总时长 90 分钟、耗材 183 元加机动 117 元等于 300 元，两轮 20 人名单各无遗漏或重复，并审阅纸笔交换及七类情境推演。此证据覆盖本案例的材料制作与交接，不证明实际活动效果或普遍跨任务增益。
