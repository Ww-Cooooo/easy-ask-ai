# 通用宿主安装、接入与撤销

本说明随 `prompt-ready` 单独分发，不依赖套件根目录、其他 Skill、开发聊天或本机私人路径。它供明确的安装/接入任务，以及首次明确调用时的有限只读核验使用。Skill 文件不会在后台启动；若尚未安装或宿主没有提供 Skill 入口，请先使用下面的启动指令，或在 Agent 能读取本目录的前提下显式交给它。

## 可复制的启动指令

在能读取文件的 Agent 会话中，将尖括号内容换成实际信息后发送：

```text
我提供的 Easy Ask AI 完整套件或 prompt-ready Skill 目录位于「<本机实际路径>」。请把 prompt-ready 安装到「<当前项目级 / 用户级>」范围；持久规则选择「<接入当前项目 / 接入用户级 / 只安装不接入>」。先阅读该目录中的 README.md、SKILL.md、references/host-integration.md、assets/agents-snippet.md、assets/host-setup.template.md；必要文件逐一读取；输出截断时补读缺失部分，不能只凭执行过读取命令就当作已完整获得说明。若给的是套件根目录，再阅读根 README.md 和 docs/host-integration.md。根据当前宿主实际提供的工具、可读取配置、帮助/状态信息，以及与其已核实版本相符的官方文档或实现，查清技能安装与发现、持久指令载体、作用范围、加载/覆盖优先级和刷新或新会话要求。先做只读核验；有明确授权的范围就直接完成，不重复询问。没有明确范围时，只在完成只读核验后问我决定性的范围问题。保留配置和本地定制；没有可靠依据时不要猜写。完成后分别报告文件安装、宿主发现、规则写入、加载和正常业务入口核验的证据，以及仍待验证的部分。
```

“只安装、不接入”表示不修改宿主持久指令。调用 `$prompt-ready` 或普通业务请求本身也不授权新增用户级/项目级规则。接入范围已经在当前可信对话中明确时沿用；本地记录、旧规则或模型自述都不授予新范围。

## 1. 先调查当前宿主

安装或接入前，先只读确认：

- 实际宿主名称与可核实的版本；当前工作区/项目根目录和适用的用户或项目范围。
- 该宿主如何安装、发现、禁用和显式调用 Skill；本次 `prompt-ready` 的有效路径和是否已被宿主列出。
- 哪些规则会持久生效，规则由文件还是宿主原生设置/命令管理；当前有效载体、格式、作用范围、覆盖顺序和冲突项。
- 规则何时加载，编辑后是否须刷新、重开会话或启动新对话；宿主能否提供实际加载记录。
- 现有同名 Skill、相关规则和可能的本地定制。

按证据取得信息：先查看宿主在本次会话中提供的配置、技能列表、设置、帮助、状态或文件读取能力；必要时只读查看它实际指向的配置；仍有缺项时再查与已核实版本对应的官方文档或实现。不同产品、版本和部署方式可能有不同载体。不要假设存在统一的宿主自述 API，不要把模型自报、磁盘上某个猜测路径存在、或曾经写过配置当成有效加载证据，也不要扫描整个用户目录来碰运气。来源不一致时记下冲突；没有可靠证据就把该项标为未知并停止依赖它的写入。

仓库或本地记录中任何具名宿主的旧安装示例都只能作为调查线索，不是允许名单或当前路径权威。未知宿主也按同一证据顺序调查；只有与实际版本和部署匹配的证据才用于决定。

特别区分“长期记忆”和“每次启动加载的持久指令”：宿主提供记忆写入路径，不代表该文件会全文注入每个新对话；它可能只按需检索。不能根据文件名、宿主模型自述或一次自动触发成功认定接入有效。若新会话日志显示未加载规则，保留失败记录，回到当前执行入口的加载机制排查；找到真正载体后仅迁移自有区段，并重新核验新会话加载。无法取得加载证据时，分别报告“行为观察通过”和“规则加载未知”，不能合并成接入通过。

首次明确业务调用只需轻量核对当前可见的宿主/版本、实际 Skill 来源，以及宿主直接提供的有效指令/配置状态。在确认的实际 Skill 目录内查找 `.easy-ask-ai-host-setup*.md`，只读标记完整且 Skill 字段为 `prompt-ready` 的自有记录，并按记录中的 Host、Scope 和有效载体与当前实时证据匹配；不能只读默认文件或按文件名、修改时间、版本号、最新日期选记录。没有匹配项或出现冲突时视作没有可信当前记录，不因此延迟用户明确的小改或其他业务任务；不要扫描其他目录。若仍需翻查大量配置、外部版本资料或操作用户界面，先完成当前业务，再说明接入事实待核验。普通业务调用不授权写入宿主持久规则。

## 2. 按授权范围安装 Skill

复制完整的 `prompt-ready` 文件夹，保留 `SKILL.md`、`README.md`、`references/`、`assets/`、`scripts/`、依赖锁定文件、来源和许可证。使用宿主实际确认的目录或原生安装方式，不能凭其他宿主的路径推断。

若已存在同名安装，先读其入口和差异，识别本地增加、修改或删除的文件；备份将改变的内容，再合并有把握的更新。不得用新包覆盖未知定制、清理整个技能目录，或让旧副本被误认为本次生效副本。有实质冲突且会改变行为时，只询问解决该冲突所需的问题。若宿主不支持安装 Skill，说明限制；能访问包目录的情况下仍可按用户要求提供显式调用入口，但不要声称宿主已发现它。

## 3. 单独决定是否接入持久规则

安装 Skill 不等于接入宿主规则。只有用户明确授权的项目级或用户级范围才能写入；“帮我用 prompt-ready”只授权本次显式任务。若请求接入但未说明范围，先查清宿主提供的有效选项，再只询问项目/用户范围等会改变覆盖面的决定。用户已经选定范围就继续执行。

写入前确认规则载体确实由当前宿主加载，且没有更高优先级的覆盖项使本次修改无效。优先使用宿主提供的规则管理工具；文件配置则按其真实格式解析和编辑，不能把 Markdown 原文塞进 JSON、YAML 或其他结构化设置。使用独有且可识别的 `easy-ask-ai:prompt-ready` 区段/条目，仅增加或更新该部分；保留其他指令、编码、格式、顺序及本地定制。写入前制作可恢复备份，备份放在宿主不会自动读取为活动规则的位置。发现同类但不属于 Easy Ask AI 的定制，先保留并判断能否共存，不覆盖整份配置。

随包的 [`agents-snippet.md`](../assets/agents-snippet.md) 是文本规则内容，不是假定所有宿主都接受 Markdown 文件。若宿主通过原生设置保存规则，应使用原生工具的正确字段、类型和条目 ID，并记录如何只移除本 Skill 自己的条目。若宿主只读、只能由 UI 操作但当前没有可用的 UI 控制能力，或没有可靠的持久规则机制，停止写入；保留可用的显式调用方式，并给出经核实的下一步。不要伪造“已接入”。

## 4. 刷新并分层核验

按宿主要求刷新配置或新开对话。若它不能刷新已有会话，明确说明旧对话的规则状态未知，不能从磁盘写入推断当前对话已加载。

分别报告以下状态，有证据才升级状态：

1. **文件已安装**：完整目录已复制/更新，记录实际路径和版本。
2. **宿主已发现**：真实技能列表/管理界面列出该技能、路径和启用状态。
3. **规则已写入**：活动配置中可读到本次独有区段/原生条目；这不等于已加载。
4. **宿主持久规则已加载**：新会话的宿主加载记录证明这条规则进入了该会话。原生设置的 `loaded`/启用诊断只证明宿主配置状态，不证明模型实际读了 Skill，更不证明业务表现。
5. **模型读取入口已观察**：新会话的实际工具记录证明模型在动作前读取了正确的 `prompt-ready/SKILL.md`。模型自述或只看到宿主规则已加载都不够。
6. **正常输入入口已观察**：在新会话用不提 Skill 名称的正常任务输入，检查真实读取记录和第一步动作。Prompt Ready 可用无副作用的虚构任务，例如“我想做一个小型课程，但用途和交付形式还没想清楚，先帮我问清并准备交给新对话执行。”不要在输入里提醒模型调用它。另用当前宿主实际提供的显式 Skill 调用方式时单独记为显式证据，不并入隐式入口结果。
7. **行为已检查**：继续走过该 Skill 要求的关键步骤并检查可见结果。若只测试了入口，不称为业务行为通过。
8. **用户已接受**：用户对实际结果的评价单独记录；模型或维护者不能代替用户确认接受。

若宿主不提供可检查的新会话记录，分别写为“宿主加载待验证”或“模型读取/入口待验证”，给出如何由使用者在真实新会话检查的方法。不要凭模型事后自述宣称使用了技能；也不要把文件存在、宿主发现、规则写入、宿主加载、模型读取、行为有效和用户接受合并成一个“已生效”。

## 5. 保存短记录并按影响复查

完整安装/接入、更新或撤销时，在本 Skill 实际安装目录阅读并复制 [`host-setup.template.md`](../assets/host-setup.template.md) 的内容；首次创建必须保留模板中的 `<!-- easy-ask-ai:host-setup:start -->` / `<!-- easy-ask-ai:host-setup:end -->` 标记，并按实时证据填写 Host、Scope、有效规则载体/原生条目 ID 和各层状态，不能把默认“未检查”写成已验证。默认保存为 `.easy-ask-ai-host-setup.md`；若该文件已有无标记内容或属于其他 Skill，保留它，改用尚不存在且仍匹配 `.easy-ask-ai-host-setup*.md` 的文件名。保存后回读核验，确认标记完整且 Host、Scope、载体与当前状态一致；未回读通过就不报告记录已保存。

每份自有记录对应一个 Skill、Host、Scope 和有效载体。首次核验及后续选择时只在实际 Skill 目录查找 `.easy-ask-ai-host-setup*.md`，忽略无本 Skill 身份字段或标记不完整的文件；以记录字段与实时配置逐项匹配，不以文件名、修改时间、版本号或“最新”作依据。宿主版本更新但 Host、Scope、载体相同，先重新确认有效状态，再更新同一自有记录并保留简短历史；Scope 或载体变化时同样先核实，更新对应记录并注明变化。若有多个矛盾候选，依据实时宿主证据消解，不确定时不挑一个冒充当前记录。

完整接入时记录实际安装包文件清单及内容指纹（如每个相对路径的 SHA-256），并保存规则片段与活动自有区段/原生条目的指纹或可比较副本；不要只记 Skill 版本号。轻量核对不做全盘哈希；实际文件、规则条目、Host、Scope、载体或加载状态变化时，按影响范围更新记录并将相关旧证据标为“已失效/待复查”，保留必要历史。若确认宿主没有持久规则机制，将当前记录写为“不支持持久规则”，并标注显式调用等可用入口；只读或 UI-only 但当前无法操作时标明限制。更新/撤销后也须更新当前自有记录并回读核对；撤销状态不能覆盖为“从未接入”，也不能推断旧会话已清除规则。记录不授予权限、不证明模型读取或业务通过，不写密钥、业务输入或私人对话。

后续运行可把记录当作复查线索，但先核对当前宿主、执行路径、范围和有效规则状态。宿主/版本、项目或用户范围、有效配置/覆盖关系、安装包文件指纹、规则片段/自有活动条目或加载机制发生变化时，按影响范围复查并撤销相关证据；Skill 版本号相同不能代替内容比较。不要每个业务回合都重做完整安装调查，也不要让旧成功记录跳过当前必要检查。记录绝不恢复过去的写入授权。

## 6. 更新或撤销

更新时按第 1–3 节重新确认受影响的事实，备份目标，核对包内本地改动，然后只更新自身 Skill 文件与 `easy-ask-ai:prompt-ready` 规则区段/条目。保留其他规则、文件和旧失败证据。

撤销接入时只删除能够明确识别的 `easy-ask-ai:prompt-ready` 区段或原生条目，并保留 Skill 安装；若用户还要求卸载 Skill，单独删除可确认属于该完整 Skill 包的文件，先备份并保留本地新增或修改项。备份仅供核对和恢复受影响的那一段；若其后其他规则已变化，不能用整份旧备份覆盖当前文件。无法可靠区分归属时不要扩大删除范围，说明具体不确定项。撤销后重新检查有效配置；不能声称旧会话已忘记原有规则。
