# 说不清时，帮助辨认差异

本例为虚构教学案例，说明如何承接不明确的回答，不是固定问卷或真实用户验收。

任务：给街区维修日写一则邀请。现稿以“让每一件旧物重焕生命”开头，连续使用“修复物件，连接温度”等表达，后面才介绍可送修小电器、需提前登记和无法保证修复所有故障。事实已确认，用户说“AI味太重”。

**Agent 先读稿，并读取 Get Clear 及正常依赖。** 观察到抽象口号，但不能断定用户所说的 AI 味就是口号。

**一问（紧扣原稿一处核心分歧，用紧凑 2 列表格对齐，不提前写大段猜测正文）：**

“你嫌‘AI味重’，但先直接改之前得对齐一件事——这句开头其实可以往两个完全不同的出口走（送修规则和不能保证修好的事实都锁死不动）：

| 这一步先立住哪一层 | 对应的直接感觉 |
| :- | :--- |
| **1. 一上来先报实用实事** | 一眼看到家里啥能修、怎么登记，像实在的社区服务清单 |
| **2. 先用一个小画面带入，再说清能修啥** | 从邻居拿着旧物来修的具体瞬间开篇，再接服务规则 |

回 `1 / 2`，或者两样都不像（直接说真正觉得别扭的地方）都行。”

**用户：**“还是说不清，都没太大感觉。”

没有获得答案，不能直接选择“先讲用途”，也不能改问“请找篇你喜欢的”。在原句同一入口上换成更易分辨的一组短句对照：

**下一问：**“那咱们不聊方向词了，直接拿同样真实的两句开头摆给你听读感（不改任何规则）：

| # | 发给邻居第一眼看到的句子 |
| :- | :--- |
| **1** | 家里有坏掉的小电器，可以先登记故障，维修日带来看看。 |
| **2** | 一盏舍不得扔的台灯，或许可以带来和邻居一起找找故障。 |

都不接近也可以直说。”

**用户：**“第一句，直接讲事情。但别写成冷冰冰的通知。”

已知先讲实际用途，不等于已经确认整篇语气、结构或所有边界。

**下一问：**“明白。那在‘直接讲事情’的前提下，你觉得哪种说话温度更像街坊聊天、不冷冰冰？

| 选项 | 邀请口气示范（均保留无法保证修好全部故障） |
| :- | :--- |
| **1** | 欢迎有维修需要的居民提前登记。 |
| **2** | 家里有坏了又舍不得扔的小电器，欢迎来登记，一起看看能不能修好。 |

也可以提哪两字太重或太轻。”

**用户：**“后面那种，像社区的人说话，但别太熟，也别夸大。”

受众、用途和事实限制已有依据，剩下专业写法由 Agent 负责。用 More Than Yes 核对是否把“亲切”扩大成装熟、把“可能修好”变成承诺，以及登记和不接修范围有没有丢；能查的自己查。若真实任务有其他会改变方向的未知，还应继续问，不机械地按三问结束。

**需求理解报告（紧凑核对表）：**

| 状态 | 范围 | 具体边界与验收口径 |
| :--- | :--- | :--- |
| **改动** | 开头与邀请表达 | 先直接说明可带小电器与如何登记；口吻自然带一点社区交流感，不装熟、不夸大、不用抽象口号 |
| **锁死** | 维修范围与规则 | 可送修小电器范围、提前登记要求、不能保证修好所有故障均保持准确，不新增维修承诺 |
| **未决** | — | 无待用户选定的方向；Agent 落地后通读核对事实、语气与登记说明是否完整 |

这份需求理解是否符合你的想法、是否完整？

**用户补充：**“不是整篇重排，只改开头两句和邀请语；登记规则和其他段落原样保留。”

**Agent 更新并重新呈现完整报告：**

| 状态 | 范围 | 具体边界与验收口径 |
| :--- | :--- | :--- |
| **改动** | 仅开头两句与邀请语 | 先说明能带什么与如何登记，保持自然的社区交流口吻，不装熟、不夸大、不用抽象口号 |
| **锁死** | 登记规则与其他全部段落 | 不重排整篇；可送修范围、提前登记与无法保证全修好等段落原样保留，不新增维修承诺 |
| **未决** | — | 用户方向与范围已清楚；回读全文核对新旧段落衔接、口吻及边界准确 |

这份更新后的需求理解符合你的想法、也完整吗？

**用户：**“符合且完整，就按这个改。”

**报告获明确认可后：**在当前任务只改开头两句和邀请语，保留其余段落；回读整篇邀请，核实登记与维修限制准确、语气自然，没有把不能保证修复写成承诺。两句提问辅助仍只是辨认材料，没有在报告获认可前写入正式成果。

**若新稿后用户又说：**“好些了，但还是太像在发通知。”沿用已确认的先讲用途、保留事实、不装熟，只重开尚未达到的交流感；结合新稿问一句具体比较。不能因为已访谈过，就凭“通知”二字再猜一整版。
