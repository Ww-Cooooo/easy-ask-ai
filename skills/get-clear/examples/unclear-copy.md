# 说不清时，帮助辨认差异

本例为虚构教学案例，说明如何承接不明确的回答，不是固定问卷或真实用户验收。

任务：给街区维修日写一则邀请。现稿以“让每一件旧物重焕生命”开头，连续使用“修复物件，连接温度”等表达，后面才介绍可送修小电器、需提前登记和无法保证修复所有故障。事实已确认，用户说“AI味太重”。

**Agent 先读稿，并读取 Get Clear 及正常依赖。** 观察到抽象口号，但不能断定用户所说的 AI 味就是口号。

**一问：**“现在开头是‘让每一件旧物重焕生命’，后面才讲能修哪些东西。你更希望一开始就知道这次能帮自己修什么，还是先看到一个邻居拿着旧物来修的具体场景？也可以都不是。”

**用户：**“我也说不清，还是不满意。”

没有获得答案，不能直接选择“先讲用途”，也不能改问“请找篇你喜欢的”。换成同一表达入口上更容易辨认的短例：

**下一问：**“我换两句具体的话帮你判断，只是辨别开头方向：‘家里有坏掉的小电器，可以先登记故障，维修日带来看看’和‘一盏舍不得扔的台灯，或许可以带来和邻居一起找找故障’，哪一种更接近你愿意发出的邀请？都不接近也可以。”

**用户：**“第一句，直接讲事情。但别写成冷冰冰的通知。”

已知先讲实际用途，不等于已经确认整篇语气、结构或所有边界。

**下一问：**“那在邀请的语气上，你更接近‘欢迎有维修需要的居民提前登记’，还是‘家里有坏了又舍不得扔的小电器，欢迎来登记，一起看看能不能修好’？两句都保留不能保证修好的事实。”

**用户：**“后面那种，像社区的人说话，但别太熟，也别夸大。”

受众、用途和事实限制已有依据，剩下专业写法由 Agent 负责。用 More Than Yes 核对是否把“亲切”扩大成装熟、把“可能修好”变成承诺，以及登记和不接修范围有没有丢；能查的自己查。若真实任务有其他会改变方向的未知，还应继续问，不机械地按三问结束。

**复述确认：**“这版先直接说明能带什么来、怎样登记，用社区邀请的自然口吻，保留一点交流感；不写抽象口号，不装熟，也不承诺一定修好。安排、登记要求和不接修范围保持准确。我会调整整篇开头、段落顺序和邀请语，再通读检查。这是你要的方向吗？”

**用户：**“对，就按这个改。”

这时才在当前任务完成整篇修改、保存并检查。两句提问辅助没有被当作整篇方案，也没有在确认前写入正式成果。

**若新稿后用户又说：**“好些了，但还是太像在发通知。”沿用已确认的先讲用途、保留事实、不装熟，只重开尚未达到的交流感；结合新稿问一句具体比较。不能因为已访谈过，就凭“通知”二字再猜一整版。
