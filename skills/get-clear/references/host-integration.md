# 可选：接入宿主工作规则

单独安装 Skill 后，模型可能看见名称和描述，却直接编辑文件而跳过读取。希望日常返修先进入 Get Clear 时，可以把随包的[读取规则](../assets/agents-snippet.md)合并到宿主会加载的指令文件。规则负责入口；完整方法仍由 Skill 提供。它不会把明确小改变成访谈，也不要求普通代码故障、文件移动或重命名走本流程。

这是一项可选安装步骤，由使用者选择作用范围。复制 Skill 文件夹不会自动改动全局配置。

## Codex 接入

1. 先安装完整 `get-clear` 目录，确认当前技能列表能找到它。
2. 选择仅用于当前项目，或用于所有工作区。项目范围合并到适用的 `AGENTS.md`；用户范围通常使用 `~/.codex/AGENTS.md`。自定义 `CODEX_HOME` 时以实际目录为准。同级非空 `AGENTS.override.md` 会优先加载，应先确认哪个文件生效，不删除覆盖文件来强行安装。依据：[Codex 指令发现规则](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。
3. 备份要修改的文件，将 `assets/agents-snippet.md` 的完整内容追加进去，保留原有文本、编码和换行。已有 `easy-ask-ai:get-clear` 标记时只核对或更新该段，不重复追加。若已有同类定制规则，先理解并合并其边界，不直接覆盖。
4. 新开一个对话，直接给一个正常返修任务，不在任务中点名技能或提醒读取，随后检查可见的工具记录。真正的通过证据是编辑或提问前读取了 `get-clear/SKILL.md` 及对应说明，并完成正确动作；只复述规则或写“使用了”不够。若没有读取，再检查规则和技能路径是否实际生效；这种诊断及之后的显式调用要与自然任务结果分开记录。

可以把下面这条指令连同包位置交给安装 Agent：

> 请安装这个完整 Get Clear Skill，并将随包 `assets/agents-snippet.md` 接入 Codex 的用户级工作规则。先检查实际生效的指令文件，备份并保留其他规则，不重复追加；完成后告诉我生效文件和如何在新对话核对读取记录。

需要撤销接入时，只移除两条 `easy-ask-ai:get-clear` 标记之间及标记本身的这一段，保留其余规则和业务文件。Skill 本身可继续显式调用。

## 验证与其他宿主

记录时区分“只安装 Skill”“Skill 加宿主规则”和“显式调用”。不要把带规则的结果写成单独靠描述自动匹配的成功，也不要把一个宿主的结果套用到另一个。

若规则没出现，先核对生效目录、覆盖文件、项目规则和宿主指令长度限制，再新开会话；不要无限堆叠触发词。若规则出现但仍未读取，保留失败和当时配置，使用 `$get-clear` 显式调用帮助判断入口与执行的差别；显式通过不代表自动选择已修好。

其他支持持久指令的宿主可由使用者选择合并同一段规则，但文件名、加载优先级和调用方式须按各宿主实际能力确认。把 Skill 同步到 DeepSeek Harness、Claude Code 或 WorkBuddy，不代表 Codex 的全局规则会同时生效。本包不自动修改这些宿主的全局配置。

这仍是一条由宿主加载、由模型遵循的工作指令，不是编辑拦截器，不能保证任意未来模型和任务都100%执行。安装后的首次检查是流程的一部分；真实业务成果仍需核验。
