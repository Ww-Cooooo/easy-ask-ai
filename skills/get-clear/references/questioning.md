# 怎样把问题问到点上

用户表达含糊时，不是让其填完整规格。结合当前作品，找出回答后确实会改变结果的一处体验差别。

## 逐轮核对实际问句

本页是 Get Clear 对下一问的唯一完整发送前检查。每次准备把问题发给用户或问答工具前，先写出将实际发送的句子和全部选项，再逐项检查、改正；收到回答后重新判断当前阶段，对下一问重复此检查。工具返回答案与普通消息适用同一流程。完整改向的复述确认另按[访谈第 4 节](interview.md#4-问清楚的判据与确认)校对。

1. **核对作品与事实。** 技能读完后，单独取回问题所依据的当前作品、简报和有效决定中的原句，不用自己的摘要代替；刚才已单独读取且仍有效的依据可复用。问题及每个选项都要有实际观察或原句支撑，并保留对象、时间/阶段、条件、范围、数值、否定及约束强度：必须、建议、可选、禁止不能混为一谈。材料冲突时先定位两处原句；能自行查明的事实不要让用户重答。没有依据的说法删去或明确为待确认，不能包装成原有要求。
2. **只辨认一处可感知的差别。** 问句要指向实际作品或已确认的用途，一轮只问一个主要决定。选项保留相同事实与功能，只改变本次要辨认的体验；不同回答应导致不同的后续选择。问用户更接近哪种结果，不让其诊断原因、挑缺点、提供专业术语或选择谁找参考。选项中性，可回答“都不是”“都有一点”或“说不清”，不推荐用户喜欢哪项。
3. **限制答案的含义。** 先检查回答里的关键用词、指代、程度和前提是否已经明确；表面上回答了题目，不代表其中的歧义已消除。仍可能导向不同改法时，按下节辨别含义。用户的回答只更新本题所测的偏好或约束，不证明你猜的原因，也不自动确定整体改向、授权修改或代表用户接受方案。没有回答、仍说不满意或说不清时，保留未决项；新增线索只解决它实际涉及的维度。
4. **让用户看得懂比较对象。** 优先用已检查的作品或参考作锚点。文字题用事实一致、质量相近且只变一个维度的短例；视觉或声音差别需要实际可见、可听的材料。用户没有自带参考不是障碍：由 Agent 查找、筛选并展示可访问的现成材料，不问“谁来找”或是否要继续澄清。现成材料仍不能显示本题差别时，可在当前已授权任务内做一份只用于辨认单一维度的临时局部对照；不改业务原件、不把它当新方案或已接受设计，也不另行索要制作许可。完整视觉、视频或方案研究仍需具体比较范围和相应授权。用户要求停止、看备选稿或委托决定时，按[访谈确认规则](interview.md#4-问清楚的判据与确认)的相应例外执行。

若实际措辞或任何选项没通过检查，先修订再发送，不靠事后附注纠正。工作记录只留足够的原句、已知偏好和未决项，不要求用户审阅过程表。反复否定、全选缺点或无法描述时，另读[多轮反馈恢复方法](repeated-feedback.md)；它决定如何更换辨认方式，问句本身仍按本页核对。

## 先分清表达含义与原因假设

用户的对象、行动和所处阶段不能被改写成你更熟悉的内容。“现在”与“这里”、“等候时怎么做”与“能办什么事”、“已经报名后”与“决定是否报名”可能指向不同结果。已有上下文能排除一种解释时直接沿用；仍有实质分歧才问用途，不索要只有某种解释才需要的详细资料。

观察到的特征、用户报告的感受、造成感受的原因是三件事。看见大字、亮色或密集信息可以成为提问依据，却不能直接说“你觉得累是因为信息太多”，再推荐删信息。没有观察证据时只说“可能”，不说“问题就是”；共同存在于多个失败版本的特征也只是候选原因。

例如，实际页面有醒目的促销数字和多个报名按钮，而用户说“不够高级”，不问“外观还是结构有问题”。可依据真实画面问：“这一版先看到醒目的报名数字和几个按钮。你更希望第一眼先明白活动有什么价值，还是先看到清楚的报名入口？也可能都不是。”只有当画面确有这些表现且两个答案会改变后续处理时才这样问；答案不能自动确认用户讨厌促销或要整体重做。

## 看似具体的回答里，仍有没说清的含义

不只判断整句话是否模糊。用户回答了问题、指出一个词、提出改法，仍可能留下会改变输出的歧义：例如“少点修饰”里的修饰指什么，“这里别这么满”里的这里是哪一部分，“把节奏放轻一点”是说声音、动作还是表达。它们是检查线索，不是关键词表，也不一律等同于要求减少内容。

先用当前原作、前一问和有效决定判断这个词在本次任务中的含义。如果已能确定，就继续，不要求用户再定义。仍有两个以上合理解释且会产生不同结果时，只保留该处为未决；明确部分不重问。选最影响下一步的一处，用原稿的短句、当前画面或可听片段把区别摆出来，问哪种表现更接近所指；允许都包括、都不是或说不清。不要泛问“请具体说明”，不要先宣布自己的释义，再让用户批准按它改全文。

把“说的是哪一处”和“那一处要变成什么”分别判断。回答若只指出“就是这圈光”，只解决对象，不代表要删除、减弱或换色；如果这些结果仍会导致不同改法，下一问继续针对同一处，只比较一个实际差别，例如“只看这圈光：维持现在的强度，还是淡一些？也可以都不是”。用原作或参考展示差别；确实看不出时，才做只改变这一项的临时局部对照。原本就明确说“去掉光晕，保留深色和状态标记”可直接执行；若它是访谈中的回答，不重问同一意思，而是记入详细需求理解报告，等用户核对认可后实施。

**虚构文案例子。** AI 问文章是否有 AI 味，用户答“你可能不该用很多的修饰”。原稿恰有“温暖而丰盛的交流会”和“让每个人都收获成长”。可问：“你说的‘修饰’，更接近‘温暖而丰盛’这种给事物加描述，还是‘让每个人都收获成长’这种替读者说效果很好？也可能两种都有，或者不是这两处。”这是借现有句子辨别含义，不是断言这两类一定造成 AI 味，也不要求用户先懂修辞术语；其他原作须换成其真实内容，不能虚构它也有这两句。

用户若答“不是不能写得美，是别替人说好”，只记录本次要减少无依据的效果评价，不扩大成删除全部形容词、比喻或缩短全文；仍未解决的范围继续问，关键含义和改向齐全后再按访谈流程确认。若答“我也说不清”，保留未知，换原文的另一处或事实相同、只改变这一处表达的短对照；不能把词换成“更自然”就宣布理解。

局部答案不是永久偏好。把已澄清的意思连同原句和适用范围保留在本任务，后续沿用；新的限定或否定只重开受影响分支。独立的明确小改如“删去首句的‘温暖而丰盛’，其他不动”直接执行；访谈中的具体回答则纳入当前报告，不再追问已清楚的含义，但也不跳过报告核对。

## 用户不知道怎样表达时

- 说不出风格名称或部位：从整体用途、第一眼感受或当前最想摆脱的印象起步，不要求指出精确像素。
- 想要“高级”但对示例无感：用途事实只有在确实未知且会改变判断时才问；用途已清楚，就比较当前作品或实际参考中可见的差别，不改问功能排序或使用习惯。
- 提供喜欢的参考：先看真实材料，再问哪种可见效果接近、哪些部分不希望照搬；与原要求冲突时只问那个取舍。
- 回答“都有一点”：允许多个目标并存，只有确实冲突才问优先级；不把不答或选择“都不是”当作默认偏好。
- 再次只说不满意：保留仍未回答的区别，接住新增线索后换更容易辨认的问法。没有新线索时改用当前作品或现成参照，不重复原题或换一组抽象形容词。
- 明说“脑子里没画面”“这些词我分不出来”或文字对照已无效：视觉任务展示能比较的实际画面，声音/动作任务提供可听或可播放材料；说明只比较哪一处。已整体否定的原稿不原样重摆。用户没有参考时由 Agent 寻找更有区分度的现成材料；确实无法展示时说明实际缺口，不能宣布方向明确。

完整方向确认前，不把两句短例包装成新稿或默认方案；喜欢某个局部也不等于同意照它重做全部。只为提出当前问题而做的单维临时局部对照按上文处理；完整视觉/视频研究稿仍须明确比较维度并取得相应授权，除非用户已经明确要求看稿或委托决定。访谈帮助弄清目标，不证明实现方式已经可行；目标确定后由 Agent 选择实现，并通过真实成果检查。
