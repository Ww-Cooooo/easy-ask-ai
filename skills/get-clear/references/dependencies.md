# 依赖定位与适配

两个必需依赖分别负责深入追问与独立判断。只有本包实际被宿主加载后才能运行检查；“把文件放进目录”不会自动运行安装钩子。

## 先识别宿主和已有安装

按以下顺序用最窄的可靠入口定位 `grilling` 与 `more-than-yes`，并读取本轮需要的完整依赖内容：

1. 宿主、当前任务配置或用户已给出确切 Skill 路径时，直接 Read 对应的 `SKILL.md` 和本轮需要的引用文件，并核对实际内容与来源记录；不先 Glob 或搜索其他副本。
2. 宿主已列出依赖名称且提供原生 Skill 加载工具时，必须直接按名称调用该工具，不先 Glob/Grep，也不要求先解析绝对路径。使用宿主实际工具定义中的技能名参数，分别指定 `grilling`、`more-than-yes`；不假设工具名或参数名统一。只有工具实际返回不可用或调用失败，才进入下一步；不能凭猜测跳过。加载成功后，沿工具返回的实际路径或包内引用读取本轮需要的说明；入口及所需依赖可读、来源可核对后即停止定位，不再找副本。
3. 宿主既无确切路径也不能原生加载时，只在宿主明确提供或确认的 Skill 根目录内枚举名称。目录枚举或 Glob 可能不遍历 junction；空结果不能证明依赖缺失、不存在或被拒绝访问。已有已知路径时直接 Read 核验，不用重复 Glob 猜路径。
4. 仍无法确认路径或读取状态时，记录为“未知”，不要写成 `missing`、无权限或不存在；不扩大到用户上级目录、业务项目、其他任务或历史验证目录。后续只按已确认的固定来源、宿主机制和安装授权处理。

原生调用只用于读取依赖。之后由[完整访谈](interview.md)管理分支与方向确认，[提问方法](questioning.md)统一检查每轮实际发送的问题和选项。继续使用 grilling 的决策依赖树与等待答案再深入的方法；其整轮问卷及推荐答案格式不用于辨认未知偏好。more-than-yes 用于检查解释和方案的依据，不替用户决定偏好；方向明确或用户已委托后，可以推荐实现手段。使用依赖不另起访谈，也不修改其安装文件。

不读取凭据，不假定依赖与本包同目录。脚本检查只用于已确认的技能根目录，不能代替宿主原生加载，也不能成为扩大搜索范围的理由。

对于 Codex，可检查宿主实际提供的技能路径和 `CODEX_HOME/skills`（未设置时为用户目录的 `.codex/skills`）；本机已暴露 `.agents/skills` 等路径时一并检查。其他宿主使用其文档或实际列表确认的目录，不把某一主机的路径写死成全平台规则。

本包脚本需要 Python 3.10+，无第三方 Python 依赖。将下列示例中的路径替换为实际绝对路径；PowerShell 使用 PowerShell 7，Windows Python 加 `-X utf8`。示例中的 `python` 应替换为本机已验证的 Python 命令。

```text
python -X utf8 "<本包>/scripts/dependencies.py" check --search-root "<已确认宿主技能根目录>"
```

多根目录可以重复 `--search-root`。检查只读，不联网、不安装。输出含每个匹配位置、必需文件可读性、`present / incomplete / missing`，不推断安装版本或当前宿主加载状态。

- `present`：保留已有包；读取确认能力与当前任务适配。与锁定提交不同不自动升级。已有定制且可用时沿用，并记录来源尚未验证的部分。
- `incomplete`：说明缺失文件，保留原目录。不能以“补装”为由覆盖；先确认能否复用其他有效副本，否则需要修复方案和相应授权。
- `missing`：已存在但不可发现的有效包应先处理发现问题，不重复安装制造冲突。确认确需补装时才读[依赖补装说明](dependency-install.md)；遵循其中的固定来源、审阅、宿主权限和现有授权要求。若当前不能补装，保留缺项状态，可继续不依赖该项的事实整理，不能冒充核心访谈已完成。
