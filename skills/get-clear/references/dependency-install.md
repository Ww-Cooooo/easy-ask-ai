# 依赖补装与锁定版本维护

仅在[依赖检查](dependencies.md)确认必需项缺失/不完整、确定无法复用现存副本且本轮确需补装时读取本页；维护者更新依赖锁定版本时也读取。普通返修中已有依赖可读且适用时，不需要加载下载和安装步骤。

## 下载、检查、安装

首次补装时告知用户“会检查两项依赖，缺失时可能从固定 GitHub 来源下载并安装”。遵循当前授权与宿主审批机制；已有授权直接继续，不要求再次确认常规补装。

唯一默认来源在[依赖锁定文件](../dependencies.lock.json)。锁定仓库、提交、包位置和下载摘要，不临时搜索同名包，不使用浮动最新版。先下载到本任务独立临时目录：

```text
python -X utf8 "<本包>/scripts/dependencies.py" fetch --dependency grilling --directory "<本任务临时目录>/grilling"
python -X utf8 "<本包>/scripts/dependencies.py" fetch --dependency more-than-yes --directory "<本任务临时目录>/more-than-yes"
```

只运行缺失项。返回 ZIP 与审阅目录。脚本检查摘要、选取的包内路径、链接/文件类型、文件冲突、大小及必要文件，保留上游 LICENSE；不会执行下载内容。

安装前由 Agent 审阅包内入口、相关参考文件、脚本与许可，确认确为目标 Skill，没有越权指令、凭据读取、无关外发或危险行为。可使用已有审查工具，但不要为了审查再制造未声明的必需依赖。摘要保证所检查的版本一致，不等于内容安全。

在宿主允许的权限下安装已检查的 ZIP：

```text
python -X utf8 "<本包>/scripts/dependencies.py" install --dependency grilling --archive "<fetch 返回的 ZIP 路径>" --skill-root "<已确认宿主技能根目录>" --reviewed
```

另一依赖同理。`--reviewed` 是 Agent 完成审阅的记录，不代替宿主授权。安装重新验证原 ZIP，不安装被改过的审阅副本；目标存在即拒绝，绝不自动删除、覆盖或升级。若写入中断，保留部分目录和错误供修复，不继续往上覆盖。

环境中未安装 Python 时，不自动安装系统运行时。Agent 可使用宿主已有且支持固定提交、整包复制、保留许可和拒绝覆盖的安装工具；按锁定来源获取、检查后安装，注明未走本脚本的验证。若只能手动操作，就给出具体路径与来源，暂停依赖流程。不要假装所有聊天网页都能访问文件和安装 Skill。

## 安装后与后续运行

重新检查文件，并尝试通过宿主正常机制发现和读取。若宿主允许直接读入口，也可按文件指令执行，准确说明这是文件加载；不声称已经注册成功。需要新会话/刷新时保存需求与依赖状态，给用户“继续准备”的指令，不让用户重述想法。不能承诺刷新时间或臆造界面按钮。

后续仅检查可用性。网络失败、摘要改变或源不可达：最多对可恢复的网络错误重试一次；摘要不符不能绕过，缺源不能换陌生镜像。列出受阻依赖、保留记录并说明恢复方式。已知事实整理等独立工作可继续，核心访谈/审查不能冒充完成。

## 维护锁定版本

维护者更新依赖时重新核查来源、提交、许可、包内容和本流程的兼容性，更新锁定文件与来源记录并实测下载。GitHub 可能重新生成不同字节的 ZIP；若摘要变化，先调查并重新审查，不让使用者关闭校验。不要把锁定更新变成每次使用的后台升级。
