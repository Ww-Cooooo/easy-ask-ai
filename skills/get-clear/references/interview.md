# 含糊反馈的完整访谈与返修

只有仍存在会改变结果的含糊期望时，读取并执行本页；明确修改走执行分支。保留以下完整判断与确认步骤，不将它简化为一题问卷。

首次进入本流程，先读[依赖准备](dependencies.md)，检查并实际读取 `grilling/SKILL.md` 和 `more-than-yes/SKILL.md`，再提出正式访谈问题。看到技能名称、安装检查通过、读了其中一项或本页摘要，都不等于已读取两项依赖。缺少且确需补装时，按[补装说明](dependency-install.md)中的锁定来源和现有授权处理；已有有效安装不覆盖。不假装调用成功；依赖受阻时只继续事实整理，保存剩余问题。

各必读文件分别读取，不将完整访谈、提问指南和依赖合并在同一次受限输出里；单个文件仍过长时分段读取。每次读取后检查工具返回是否提示 `truncated`、省略或输出超限。发出读取命令不等于完整内容已经返回；已经合并且出现截断时，单独补读缺失文件或段落，看到本分支必读材料后再提问或编辑，不凭标题、摘要或文件尾部可见就断言中间没有遗漏。已经完整返回的内容无需重读。

## 含糊反馈先澄清

每次收到对当前成果的否定或修订反馈，先结合已知上下文判断：**用户是否已明确或确认本次要改变的体验、希望达到的结果及有效边界？** 判断依据是用户的表达与有效决定，不是自己已经能写出一个合理版本。若存在会导致不同改法的解释，立即进入本流程。无需用户点名、要求“先问我”或先给完整参考，也不先请求是否愿意被追问。触发不限于上面列出的词。

**材料充分不等于效果已确认。** 简报中的受众、用途、时间、流程、功能和禁止事项限定了可行范围；它们不能自动解释本轮“更有吸引力”“不要这么生硬”等感受。同一组事实仍可写成不同的语气、重点或体验。先用这些事实排除不合适的改法，再问仍会改变结果的一处偏好，不重问已知事实。读完材料后，即使很容易想到改法，也不能据此把含糊分支改判为已确认并直接制作。若材料确实记录了用户对本次同一改向的有效确认，可沿用并指出依据；普通事实清单或你的判断不是该依据。“请改好”“Please fix it”是动作请求，不等于明确委托你自行决定尚未说明的整体效果。

- “AI味重”“不像真的”“还是不满意”：是尚待解释的感受，不是已经确定的错句。即使你看见口号、渐变或僵硬动作，也只能把它当作提问依据，不能当成用户确认的原因。
- “不够高级，再优化一下”：只有评价和动作授权，没有消除风格、内容或体验的分歧；先问，不能把“优化一下”当作任意改方向的委托。
- “好点了，但还是不对，再参考某种做法改得有意思”：部分肯定没有回答剩余的不满，参考做法也没有确定想要的体验。先读现有方案与参考，再用其中可感知的差别问一个问题；不能直接把方案换成参考做法，或认为这是普通方案优化而跳过澄清。
- 对追问回答“你可能不该用很多的修饰”：有建议但关键含义可能未清；先按[提问方法](questioning.md)结合原文辨别所指，不自动变成删形容词、去比喻或缩短全文。其他词的指代、程度和隐含前提同样处理；上下文已明确的含义不重问。
- “第二段删掉，标题改成‘报名开始’，其他不动”：已明确，直接做，不启动访谈。
- 同时包含具体问题和整体不满：同一模糊返修中的操作一起纳入报告并等待认可，不能用局部线索代替整体追问；独立的明确任务仍可直接完成。
- 用户同时建议“换图片、加动画、学某个工具、换一种写法”：这是可调查的方法线索，不等于已经说明想要的整体效果。可以先学习、核实工具与材料；整体期望未清楚时仍需追问，不能读完技能就宣布一套新方向并开始制作。
- 用户只是引用别人说“不好看”，或正在讨论/创建本技能：完成当前讨论，不把引文当作当前作品的返修命令。
- 纯技术故障先调查，不用审美问卷诊断报错。用户已明确新方向或已确认同版方案时，沿用答案。

**领域技能负责怎么做好，Get Clear 先查清这次要改成什么。** 正在使用润色、设计、视频等技能，或以前读过 Get Clear，都不免除本轮判断。用领域方法发现的问题可以成为假设，不能代替用户偏好；进入访谈后由本流程负责提问与确认，方向确定再回到领域制作。用户明确委托自行决定时按第 4 节执行，不强行访谈。

只在宿主已向 Agent 暴露本技能入口时才能自动选择。描述是选择依据，不是后台拦截器；文件存在、列入技能表、实际读取、行为有效分别验证。入口不可见时按 [安装与接入](../README.md) 处理，不声称正文可以强制所有宿主触发。

## 1. 读现状，暂停依赖猜测的改动

读取本次反馈、当前相关要求、用户已认可/否定的方向和具体作品。能打开页面、播放片段或读取文案就先看；代码和作者自述不能代替实际体验。只读本任务相关材料，不默认搜索使用者的其他聊天。无法观察时明确缺什么，让用户补足必要材料或用他们能描述的体验追问，不能虚构“我看到”。

区分：用户原话、自己观察到的现象、尚待确认的原因。整体不满不能被你最容易修的一处问题替代。已有要求未落实时承认并处理该偏差，但仍核对是否还有未明确的目标。

复述用户回答时保留其**对象、动作和时间/所处阶段**。若换一个词就会改变用途，先辨别这层含义，再问实现或材料。例如“等候的人现在能做什么”可能指等待时可以采取的行动，也可能指这里能办哪些事项；不能自行改写成“介绍服务”，然后让用户补齐服务清单。现稿正在介绍什么，不代表用户还想继续介绍它。已有上下文足以排除一种解释时直接沿用；否则用一句对照问清，别让用户先为未经确认的方向准备材料。

保留当前成果；**在用户含义未问清前，不替换方案、不制作猜测方向的新版本，也不把“先做可逆小样”当作绕过提问的办法。** 调查资料、读取作品和检查事实可以继续。为一个尚未明确的感知区别制作临时局部对照，按提问方法限制比较范围，不修改业务原件，也不当作新方案交付。可以提出假设，不能先宣布“你要的就是某种风格”。

## 2. 调用 grilling，一次问一个决定性问题

进入访谈前读[提问方法](questioning.md)。它是每轮实际问题和选项的唯一发送前检查；按其中的逐轮关口核对将发送的文本，修正后再问。沿用 grilling 的决策依赖树和等待回答再深入的方法，但每轮只问一个主要决定，不发整套规格表；缺少事实先查材料，需要用户补充时再单独问，不与偏好或整套方向确认捆绑。

每次收到回答后更新当前任务里的已知、仍未知和已替代内容，再判断是否解决了原来的区别，以及回答自身有没有留下影响改法的新歧义。提问工具在同一长回合返回的答案也一样处理；一个偏好答案只补齐所测维度，不等于整体方向已确认。若仍被否定、全选缺点或无法回答，下一问前读[反复反馈恢复方法](repeated-feedback.md)，用其中的方法换一种辨认途径；它不替代上述问句检查，也不要求每轮重读已经有效的全部材料。

当前作品和已有参考由 Agent 检查。用户没有自带参考时，按提问方法取得可访问的对照，不把提供参考当作继续访谈的前置条件。短例或临时局部对照只作辨认辅助；制作完整视觉、视频或方案须有具体范围和相应授权。用户明确要求停止、看稿或委托决定时，按第 4 节的例外处理。文案迁移示例见[说不清时的完整访谈](../examples/unclear-copy.md)，不可把示例原句套到别的作品。

## 3. 调用 more-than-yes，检查理解是否站得住

在答案逐渐明确后，核对自己的解释与方案，而不只复述“明白了”。主要检查：是否把整体问题缩成局部、是否漏了受众/使用情境、是否引入用户不喜欢的方向、是否与已接受内容冲突、资源和工具能否达到要求。

只补会改变结果的缺项。会改变用户结果、范围、成本或偏好的补充，回到一次一问；不要把模型建议记成用户决定。能查明的事实自己查，已经委托给你的实现由你负责。

## 4. 问清楚的判据与确认

停止条件是**共同理解有据可查**，不是声称“100%知道用户脑子里的画面”。先区分三种事实：用户不满所指、希望产生的替代效果、执行依据。只找到不满对象时继续问替代效果；原本就是明确操作与边界的小改直接执行。访谈中的具体回答补入本次报告，不跳过报告核对。进入含糊访谈后，待所有会改变本次改法的分歧问清，再按本节交付完整的需求理解报告，询问用户是否符合其想法、是否完整。报告获明确认可后才实施。明确小改、已确认且无新歧义的方向，以及用户明确要求停止、看稿或委托决策的流程例外，仍按下文处理，不被报告步骤拦住。本次返修涉及的以下内容都应明确或获用户明确委托：

- 用户哪里不满意，以及希望产生什么整体感受/用途结果；不能只留下“更高级”等同义词。
- 回答能落到当前作品的具体表现，并有能比较的例子、行为或效果描述。
- 哪些内容、能力和已接受方向要保留，哪些方向明确拒绝；全局换方向与局部修改已经区分。
- 影响结果的主要取舍没有悬而未决；专业实现选择由 Agent 承担，不要求用户逐个确定数值和工具。
- Agent 能解释下一版改哪些地方、为何有助于该目标、怎样检查；诊断假设仍标为假设。

### 访谈结束后，交付需求理解报告

这是**从辨认转到报告待核对**，不是从辨认直接转到制作。先核对当前这次返修的阶段及最近有效授权：若此前委托的成品已经被整体否定，那次委托已结束；随后用户答清整体期望、顺序、保留项和禁止项，只使报告可以写，不会恢复旧委托。报告尚未发出时不存在“用户已认可当前报告”。这一步先交可见的完整报告并询问，等待下一次答复，不边写报告边制作。只有用户另行明确要求现在看稿或直接委托制作时，才走原例外。

**先核对收束依据，再决定是否能发报告。** 在当前工作记录用一句原话指出替代效果来自用户哪次回答、哪项有效的同改向确认，或哪句有效委托；不要求新增文件或给用户看自检表。若依据只有用途事实、Agent 的专业判断或“用户说不清/别问我”，替代效果仍未明确，下一步是具体辨认，不是报告核对。不能把整套假设风格、正确的事实保留清单与验收方法拼成报告，再让用户批准；写“这是我的推导”“如不对请纠正”也不补足缺失的答案。报告用来核对已形成的共同理解，不用来把未回答的偏好转交给用户审整套设计。

只有所有会影响结果的用户层面分歧都已问清，才把访谈收束为可审阅的需求理解报告；若仍有这类未决项，继续针对它追问，不把报告说成已完整。报告在当前对话中直接可见，按实际任务充分展开目标及关键原话含义、拟改内容、要保留或排除的内容、事实和范围边界、仍未决的事项、实施依据与验收方法。没有未决项时明确写“无”；非阻塞的实现取舍由 Agent 负责，并标成方案或假设。报告内容以当前原作、有效用户决定和可核实事实为依据，不凑字。

把用户已明确/认可的要求、材料事实、Agent 的诊断假设与建议分别标清。建议和假设不能写成用户决定；报告用于说明理解，不是完整返修正文或未经确认的新稿。明确问用户：“这份需求理解是否符合你的想法、是否完整？”报告在当前对话直接可见；篇幅较长时可另存并给出实际链接，但不以新窗口、任务或 PromptReady 交接替代当前审阅。

用户补充、纠正或表达新偏好时，视为报告内容有变化，不视为认可当前报告。只重开受影响的分歧，保留已经确认的内容；必要时继续追问，再更新并呈现完整的当前报告，重新询问是否符合且完整。只有用户明确认可当前这份报告，才按其中授权的范围实施。用户明确要求停止或改变流程时尊重其决定；停止就保留未决状态，明确要求看稿或委托本次取舍则按相应范围处理，不冒称报告已获认可。

### 发出报告前，先自行核对并纠正

用户审阅的是需求理解，不是替 Agent 校对事实。准备报告及“是否符合、是否完整”的问题时，先完成以下检查，再向用户呈现。对父 Agent 转达也一样；只在附注里提醒正确条件，却让实际报告保留错误，不算纠正。

1. **取回依据。** 使用当前原稿、相关简报及有效用户决定中的原句，不从自己上一轮摘要反推事实。原句仍在可见上下文时沿用，否则重读相关部分。分别识别具体动作的必须、建议、可选、禁止，以及条件、例外和数值范围；没有写“必须”的操作指令也可能是要求，不能只搜关键词。改善语气不改变这些条件。
2. **对照准备发送的报告。** 在当前任务的工作记录中简短列出 `原句及出处 → 动作/约束与适用范围 → 报告对应内容 → 相符或需修正`。只记录可核查事实与结论，不输出完整内部思考；不必新增文件，也不要求用户审表。报告须让用户看见本次改动所依据的事实、决定、范围与保留条件；不影响方向且由 Agent 负责的实施细节可标明将在执行时核对。报告中的每个事实、承诺和条件都要有依据，用户偏好与 Agent 的实施选择分开。
3. **检查整句及重复提及。** 同一动作前面说“需要”、后面说“可以选择”，并不会互相抵消；检查所有提及并统一到原条件。并列动作也分别核对，不能让某个“可选”“无需”“必须”覆盖本来不同的事项。例如，虚构材料写“提交时附成绩单；作品集自愿提供”，拟写“可附成绩单和作品集”就改变了第一项；改成“提交时附成绩单，作品集自愿提供”，再核对。检查语义与作用范围，不机械替换所有“可以”，也不把可选项一律改成必须。
4. **改完再发。** 发现自己的错漏，直接修正报告，并用同一原句复查修正处及相关重复表述；不得把有误版本发出去等用户指出。确认实际要发送的报告与核对记录一致，才请用户审核其想法是否吻合、内容是否完整；等待明确回应，普通消息和同一长回合问答工具答案都按相同规则处理。既有记录只用于工作，不把核对表、错误草稿或长篇自检过程塞给用户。原材料确有冲突或缺失、自己无法判定时，问那个真实缺项；不要要求用户重新回答材料已写清的条件。

用户只是要求继续落实同一已确认方案，且没有新的未决反馈时，直接沿用。用户对实现后的效果又给出含糊评价时，只保留仍有效的事实、约束和局部决定，重新辨别本轮的新含义；目标名称相同，不代表这次反馈已由旧确认回答。**委托只对那一次产出有效；该产出被整体否定后，委托失效，回到第 1 节读现状并重新问一处，不能沿用旧委托自行再做一版。** 只有能对照明确原要求定位的具体执行偏差才直接纠正。确认有误只重开受影响分支；沉默、超时、“随便”“我也不知道”都不能自动变成赞成某个方向。

**回答追问或补充偏好不等于认可报告。** 例如，用户回答“用店铺账号，亲切一点但别装熟”，只是补齐偏好；把它纳入报告并继续问仍未解决之处。待分歧问清后呈现完整报告，只有用户明确认可当前报告才进入执行。若用户明确改变流程，例如“这些就是要求，不用再确认，直接做”，按其明确授权范围执行；不得把普通补充、对单项的认可或“差不多”自行当作报告整体获批。

报告轮交付的是**需求理解、拟改方向及保留边界**，不是完整返修正文。这不只是“暂时不写文件”：不要把整篇改稿先贴出来，再用“预览”“确认后保存”绕过用户审阅需求的步骤。可以用一句短例说明某个表达区别，但不能在报告获认可前完成整篇新版本。认可后才制作、保存并检查实际成果。

### 征求意见、委托与拒答

征求专业意见不是授权决定：“你觉得呢”“你比较懂”“你觉得怎样设计比较好”允许 Agent 简述推荐及依据，仍留在澄清分支；推荐只谈当前一处差别，不连带决定主视觉、字体、配色和布局。**推荐不替代辨认，本轮仍须落到一个具体效果问题，不能只给整套设计建议收尾，也不把问题变成“按我这套做吗”或对整份猜测报告求认可。** 不据此制作新版本。只有用户明确把**本次方向取舍及制作**交给 Agent，例如“这版你定”“不用再问我，按你的来做”，才按授权范围执行，不重复索要确认。判断完整语境，不按某几个字放行；“你不要问我呀，我没有审美”本身没有交出决定和制作权，也不说明用户已喜欢某个方向。“别问我这些专业的东西”改变的是问题形式，换具体表现帮助辨认，不视为退出访谈。明确要求看备选稿时只按给定范围试作，标明未知项，不冒称方向已确认。

用户只是答不出时，按提问方法换更易辨认的问法；用户拒答或明确不愿承担专业判断时，先按[拒答当轮的问句构造](questioning.md#拒绝专业判断时先交可回答的一问)，用已观察作品的一处客观表现，问普通的观看或使用感受，给**同一问题的三个具体可辨认答案，加“都不是／说不清”**并等待。这是三个可选答案，不是先制作三个新版本，也不要求用户懂设计术语。对这处仍拒答时，允许提出一项只改变一个维度的局部假设；**在生成任何辅助材料之前**，先在对话明确写“**这不是你的选择，是待你否决的假设**”及仅比较哪个局部，再按[局部对照的规模线](questioning.md#局部对照的规模线)展示；不改原件、不作交付、不称为已确认方向，也不连做整版来代替澄清。无需为了假设而新制材料；现有作品加一句短例足够时直接使用。得到线索后继续既有访谈与报告闭环，不新增确认环节。

专业判断和完整产物分开授权：“别让我来决定设计”“专业的你负责”不等于“现在做一版”。准备完整新版本前，核对用户原话是否真的授权本轮取舍及制作，不能用早先一般返修请求或交付路径补足。有效委托如“这次你定，直接给我一版”，以及明确要求按给定范围看备选稿，仍按相应范围执行，不冒称方向已确认；未获这些依据时，不因连续拒答而扩大局部试探。

用户明确撤回访谈或暂停任务时停止，并保留未决状态，不强发选项或假设；不把“我没有审美”这类求助自动解释为撤回，也不以不断追问阻止真正的撤回。

## 5. 留在当前任务执行，并用结果验收

用户明确认可当前需求理解报告后，立即继续其中已获授权的业务任务：按需求使用相应领域工具/技能完成实际修改，而不是只交建议、访谈记录或执行 Prompt；不另等一次“请继续”。明确改变流程或委托本次取舍的，按用户授权及第 4 节对应例外继续。**默认在当前工作区当前对话返修，不要求用户换窗口。** 用户明确要交接时才转为 Prompt Ready 准备流程。

进入本节时读取 [执行与精确修改](execution.md)。没有尚待回答的问题或实际工具阻碍，就在本回合执行，不把“准备开始”“接下来会修改”当成最终交付，也不等待用户再说一次“继续”。

首次修改前核对执行依据：用户在哪一轮明确认可了当前报告，或明确改变流程并授权实施。只找到“这处让我不满意”或某一项偏好回答时，不进入实施；报告尚未获认可时，停在核对步骤。改写表现方式时保留已知事实的含义，包括金额、时限起点、条件和例外；发现它们与效果目标有取舍，先说明并询问，不能先删改再让用户补选。

对照确认的整体效果和具体表现检查成果。网页看实际页面与相关交互；视频看相关完整片段并在声音涉及时听声音；文案完整阅读；工程检查对应行为。只能检查代码或静态文件时，说明未验证的体验，不能把格式/构建通过当作“高级感通过”。主观满意仍由用户对真实成果判断。

再次被否定时，把原目标、修改内容与最新感受对在一起，问新的决定性问题。每轮重新核对仍未解决的分歧；之前执行过一次访谈，不代表之后的模糊反馈可以直接按猜测改。不要反复发相同问卷，不因“已按指令做”判定用户不合理；“比之前好”也不自动表示整体通过。

多轮或中断时，在现有任务记录中保存原话摘要、已确认效果、排除/保留项、待问问题及当前阶段。没有记录约定才用 `.get-clear/<task>/requirements.md`，不覆盖同名别的任务。只有一个置顶的当前状态；历史候选和过时答案不能复活为当前决定。简单回合可留在当前对话，不为每一问造文档。

完整虚构示例见 [网页返修访谈](../examples/landing-page.md)；其他任务的提问迁移见 [跨任务示例](scenarios.md)。本包不授予新的数据读取、付费、发布或全局修改权限，也不保证一次访谈就达到所有审美目标。
